```
                └─ *_dsi.json ────────┘        │

                                        │ 심각도 분석   │ → 귀무

                                        └──────────────┘
```

## 1.2 핵심 수식

**결합 위험지수 (CDI)** — 교차로 단위

```
CDI = (w_s·R_dsi + w_t·R_aadt + w_v·R_resid) / (w_s + w_t + w_v)

  R_x     = 백분위 순위(0~1)  ; 분포 가정 없이 척도를 맞추기 위함
  R_resid = 순위(R_veh − R_aadt 로 예측한 R_veh)
                             ; 통행량 성분을 뺀 "초과차폐" (D-13)
  w_s : w_t : w_v = 1 : 2.47 : 0.40~0.96
                             ; 빈도모형 계수비, **순위 척도** 추정 (D-14)
                             ; w_v 는 두 유도 경로가 수렴하지 않아 구간 (X-15)
  ★ R_veh 원지표를 쓰면 통행량을 두 번 센다 (rho +0.496, 공유분산 24.6%)
```

**빈도모형** — 엣지 단위, 계측점 500m 이내

```
logit P(사고위험지역과 교차) = β0 + β1·z(DSI) + β2·log(길이) + β3·log(교통량) + β4·폭
  표준오차 : 최근접 계측점 군집 강건 + 와일드 군집 부트스트랩 (Rademacher, 제약 귀무)
  ★ 도로등급은 넣지 않는다 (D-04)
```

**심각도** — 구역 단위

```
심각도 = (총사망자수 + 총중상자수) / 총사고건수
```

# §2. 결정 기록

## D-01. 세부링크 도로위험지수 API 는 정적 DSI 검증에 쓰지 않는다

`opendata.koroad.or.kr/data/rest/road/dgdgr/link` 는 **실시간 5분 주기** 지표다. DSI 는 촬영일
교통과 무관한 구조적 속성이므로 성질이 다르다. 같은 구간을 여러 시각에 반복 수집해 평균을
내면 시점 편차는 줄일 수 있으나 호출 수가 배로 든다.

여기에 커버리지 문제가 겹친다 — 미매칭 구간이 절반 가까워(주요 시내 도로 172/302 세그먼트,
57%) 노선 전체 비교가 아니라 매칭된 구간만의 부분 비교가 된다. **구도심 이면도로에서 특히
비어 있는데, DSI 가 높게 나오는 곳도 주로 이런 구간이라 하필 겹친다.**

→ 수집 코드(`koroad_client.py`, `run_bus_routes.py`, `run_gangneung_bus.py`)와 수집분
(`gangneung_bus_dgdgr.json`)은 보존하되 본 분석에서는 쓰지 않는다. 참조: X-01 · X-02.

## D-02. 포털 CSV 가 API 를 전량 대체한다

강릉 64건의 `사고위험지역id` 가 API 수집분과 **완전 일치**했다. 연도별 건수·사고수는 물론
2023년만 `51150`(강원특별자치도)이고 나머지는 `42150`(강원도)인 코드 불일치까지 동일하다.

CSV 가 나은 점 — 전국 전 연도 일괄 / 허용량·페이징·차단 없음 / 시도코드 분기 불필요.

**함정: 법정동코드 전환 시점이 데이터셋마다 다르다.**

| 데이터셋 | 42 / 4215 | 51 / 5115 |
|---|---|---|
| 링크기반 교통사고 위험지역 | 2017~2022, **2024, 2025** | **2023만** |
| 지자체별 교통사고 다발지역 | 2018~2023 | 2024, 2025 |

한쪽 규칙을 다른 쪽에 적용하면 **에러 없이 빈 결과**가 나온다. `startswith(('4215','5115'))`
처럼 양쪽을 받아야 한다.

원본 헤더 오타도 있다 — 링크기반 CSV 의 총사고건수 컬럼명이 **`츙사고건수`** 다.

## D-03. 심각도 결과변수는 `(사망+중상)/사고건수`

사고 건수는 교통량에 비례하므로 노출 통제 없이는 해석할 수 없다. 반면 **사고가 났다는 조건
하의 심각도 비율은 노출도가 상당 부분 약분된다.** 이론적으로도 맞다 — 시야 차폐는 발견을
늦춰 충돌속도를 올리므로 빈도보다 심각도에 먼저 나타나야 한다.

대가는 표본이다. 지점 3.4만 개는 DSI 집계에만 쓰이고 검정의 n 은 구역 수(61)로 떨어진다.
대신 유사독립이 확보돼 p값이 의미를 갖는다. 결과는 X-03 — 귀무.

## D-04. 도로등급을 통제변수로 쓰지 않는다

측정 결과 **도로등급과 DSI 의 Spearman rho 가 +0.633** 이다. 통제하면 DSI 분산의 40% 가 함께
사라진다. 교란변수이면서 동시에 관심변수의 대리라서, 통제하면 과소추정 쪽으로 편향된다.

해상도도 부족하다 — 강릉시내 2,664개 도로구간이 등급 3개로만 나뉘고 **2,218개(83%)가 같은
등급 4** 다. 같은 등급 안에서 강릉대로와 한적한 이면도로가 한 칸에 들어간다.

**교통량은 DSI 와 rho +0.188 이라 통제해도 DSI 분산의 96% 가 남는다.** 노출 통제변수로서
이상적인 성질이다 — 결과와는 연관되고 관심변수와는 거의 무관하다. 교통량 확보의 실질적
가치가 여기에 있다.

## D-05. 도로폭은 통제한다 — 억제변수이기 때문

도로폭을 넣기 전과 후로 결과가 뒤집힌다.

| 모형 | OR (DSI 1SD) | p |
|---|---|---|
| 길이 + 교통량 | 0.984 | 0.83 |
| **+ 도로폭** | **1.226** | 0.0037 |
| + 계측점거리만 | 1.015 | 0.85 |

우연이나 사후선택이 아니라 **억제(suppression)** 구조다.

- 도로폭 ↔ DSI: rho **−0.376** (넓을수록 트여 DSI 낮음)
- 도로폭 ↔ 사례: rho **+0.123** (넓을수록 사고밀집 확률 높음)

폭이 DSI 를 끌어내리면서 동시에 사고를 끌어올리니, 통제하지 않으면 두 경로가 상쇄돼 DSI 가
무효로 보인다. 계측점거리는 단독 투입 시 무영향(1.015)이라, 이 효과가 거리 통제로 만들어진
인공물이 아님도 확인됐다. 상세: X-10.

**주장 문장에는 반드시 조건이 붙어야 한다** — "같은 도로폭·같은 교통량에서". 무조건부로는
효과가 0 에 가깝다.

## D-06. 교통량은 교차로 단위로만 쓴다

링크 보간을 **네 가지 방식으로 시도해 전부 실패**했다 (X-07 · X-08 · X-09).

| 방식 | 최고 성능 | 배수오차 중앙 |
|---|---|---|
| 전체망 중심성 + 폭·등급·도심거리 회귀 | CV R² 0.185 | 1.38배 |
| 주요망 한정 | CV R² 0.203 | 1.37배 |
| 공간 IDW (최근접 3개) | LOO R² 0.244 | 1.38배 |
| 표준노드링크 노드 단위 | CV R² 0.186 | 1.35배 |

**근본 원인은 관측 단위 불일치다.** 교통량 자료는 *교차로 진입량*이지 링크 통과량이 아니다.
한 링크에 스냅해 그 링크의 차로수로 설명하려는 시도 자체가 무리였다. 노드 단위로 옮기면
상관은 살아나지만(X-09) 예측 성능은 여전히 부족하다.

→ 자료의 원래 단위를 지킨다. 결합 지수는 교차로에서만 산출하고, 구간(링크)은 DSI 단독으로
평가하는 **이원 구조**로 간다.

**시점**: 교통량은 2025-08~2026-07, 사고는 2017~2025 로 어긋난다. 그러나 노출 통제에 필요한
것은 절대 교통량이 아니라 **교차로 간 상대 순위**이고, 그 순위는 시차가 늘어도 무너지지
않는다(X-11). 2024-09 자료로 내려가면 11개월을 앞당기는 대신 계측점이 104 → 80개로 23%
줄어든다 — 9년 격차에서 11개월은 무의미하고 커버리지 손실은 즉각적이다. **최신 자료를 쓴다.**

## D-07. 결합 가중치는 빈도모형 계수비에서 유도한다

임의 가중치를 피한다. 빈도모형(n=3,688)의 계수를 같은 1SD 단위로 환산한다.

```
DSI 1SD(=0.2078) 당 계수        +0.2013     (OR 1.223)
log교통량 1단위 당 계수          +0.8065     (OR 2.24)
log교통량 1SD(교차로, 0.4876) 당  +0.3932

→ DSI : 통행량 = 1 : 1.95
```

"동적 조건이 구조적 안전보다 크게 작용할 수 있다"는 가설이 이 비율에 수치로 들어가 있다.

**한계**: 이 계수는 링크기반 위험지역을 결과로 삼은 모형에서 나왔다. 다른 결과변수(심각도,
실제 사고율)에서는 비율이 달라질 수 있다. 가중치를 바꿔 민감도를 함께 제시해야 한다.

## D-08. 차량 차폐를 불법주정차 대리로 쓰되 그 이름으로 부르지 않는다

파이프라인 산출물에 이미 있다 — `road_occluded_frac_veh − road_occluded_frac` 이 **차량이
만든 추가 차폐**다 (루트 D-09 · D-15 참조).

| 지표 | 중앙 | 평균 | p90 | max |
|---|---|---|---|---|
| `road_occluded_frac` (구조물) | 0.0990 | 0.1748 | 0.4672 | 0.9716 |

## D-12. 결합 영향권 반경은 75m

세 기준이 모두 100m 보다 작은 쪽을 가리킨다. 근거 실험은 X-13.

**① 구성타당도 — 결정적 기준.** 교차로 주변 DSI 를 배경(400~600m)과 비교하면

| 거리대 | 배경 대비 초과 | 95% CI (군집 부트스트랩) |
|---|---:|---|
| 0~25m | −0.0973 | [−0.123, −0.070] |
| 25~50m | −0.0575 | [−0.081, −0.030] |
| 50~75m | −0.0306 | [−0.058, −0.004] |
| **75~100m** | −0.0090 | **[−0.041, +0.023]** ← 배경과 구분 안 됨 |

75m 까지가 교차로 고유 신호다. **100m 를 넘으면 "이 교차로"가 아니라 "이 동네"를 재게 된다.**

**② 기하 — 이웃과의 중첩.** 계측 교차로 최근접이웃 거리는 중앙 338m · p05 173m.
영향권이 이웃과 겹치는 교차로 비율이 75m 5% → 100m 13% → 150m 43% 로 급증한다.

**③ 표본 확보.** 60m 부터 교차로 75개가 전부 `n_pt >= 5` 를 만족한다 (50m 73개, 30m 62개).

**반대를 가리키는 기준 하나는 기각했다.** 집계평균의 신뢰도만은 반경이 클수록 좋아진다
(유효n 기준 75m 0.819 → 100m 0.849). 이득 +0.030 에 중첩 2.5배는 치를 값이 아니다.

**이 결정의 영향은 작다.** 100m 대비 CDI 순위상관 **+0.982**, 10위 이상 이동 3/75,
상위 10 중 9개 유지. 방어 가능한 선택이되 결과를 뒤집지 않는다. 크게 움직이는 것은 DSI 항
단독(rho +0.900, 21/75 이동)이고 CDI 에서는 통행량 항이 그 흔들림을 잡아준다.

**D-11 의 100m 와는 다른 파라미터다.** 그쪽은 반복 지점 군집 임계값이다. 같이 움직이지 않는다.

## D-13. 동적 2번 항은 차량차폐 원지표가 아니라 통행량 잔차

D-08 에서 "두 동적 지수가 독립이 아니다" 라고만 적어둔 것을 실제로 쟀다. 겹친다 (X-14).

- 차량차폐 ~ 통행량 rho **+0.496**, 공유분산 **24.6%**
- 도로폭을 통제해도 **+0.476** — 폭이 매개가 아니다
- 원지표를 그대로 쓰면 통행량이 1번과 2번 항에 나뉘어 들어가 **두 번 세어진다**

**조치**: 2번 항을 통행량 회귀의 잔차로 바꾼다.

```
초과차폐 = R_veh - (R_aadt 로 예측한 R_veh)
```

| 항 | 통행량과의 rho |
|---|---:|
| 차폐(원지표) | +0.496 |
| 통행량몫 — 버리는 성분 | +1.000 |
| **초과차폐 — 2번 항** | **+0.049** |

분해는 완전하다(잔차 오차 2.8e-17). 버리는 성분은 **1번 항이 이미 100% 담고 있으므로
정보 손실이 아니라 중복 제거**다. 항은 여전히 셋이고 통행량은 1번에만 나타난다.

**이름도 바꾼다.** `차량 점유로 인한 추가 차폐` → **`통행량으로 설명되지 않는 추가 차폐`**.
불법주정차 대리로는 이쪽이 맞다. D-08 의 명명 주의(주차·정차·주행 미구분, 스냅샷 1회)는
그대로 유효하다.

**지수 값에는 거의 영향이 없다.** 원지표판과 순위상관 **+0.990**, 10위 이상 이동 **0/75**.
순위를 바꾸려는 조치가 아니라 **해석의 정당성을 위한 조치**다. 다만 시나리오 효과는 읽기
쉬워졌다 — `장안교차로`(통행량 하위 5%, 초과차폐 상위 1%), `경포초사거리`(하위 21%,
상위 0%)처럼 통행량으로 설명되지 않는 곳만 올라온다.

**가중치 유도의 전제가 된다.** 결합모형에서 뽑는 계수는 상대를 통제한 부분효과다. 그
부분계수를 서로 상관된 원지표에 곱하면 겹치는 24.6% 를 다시 두 번 센다. **잔차화된 입력과
부분가중치는 세트로만 성립한다.** `w_v` 의 단위도 "차폐 1단위당" 이 아니라 **"초과차폐
1단위당"** 이므로 유도를 같은 조건에서 해야 한다.

**한계**: 순위 위 **선형** 분해다. 관계가 비선형이면 통행량이 조금 샌다 (측정된 누수 +0.049).

## D-14. 가중치는 순위 척도에서 유도한다 — D-07 의 SD 환산을 대체

**D-07 의 `1 : 1.95` 는 척도가 섞인 값이었다.** SD 를 어느 단위에서 취하느냐로 비율이 흔들린다.

| SD 출처 | `w_s : w_t` |
|---|---|
| 엣지로 통일 | 1 : 1.85 |
| 교차로로 통일 | 1 : **4.49** |
| D-07 (DSI 는 엣지, 교통량은 교차로) | 1 : 1.95 |

DSI 는 영향권 평균을 내면 SD 가 **0.208 → 0.091** 로 줄고 교통량은 교차로에서 직접
재므로 안 줄어든다. 그래서 어느 단위를 쓰느냐가 2.4배 차이를 만든다.

**해법 — 지수가 쓰는 척도에서 바로 추정한다.** CDI 는 백분위 순위로 결합한다. 그러면
예측변수도 순위로 넣어 계수를 읽으면 된다. 순위는 어느 단위에서 매기든 균등분포라
**환산 자체가 없어진다.**

빈도모형(엣지 n=3,706, 사례 647, 계측점 75군집 강건 SE):

| 항 | 계수 | SE | z | VIF |
|---|---:|---:|---:|---:|
| `R_dsi` | +0.9583 | 0.3286 | 2.92 | 1.53 |
| `R_aadt` | +2.3654 | 0.8248 | 2.87 | 1.06 |
| `R_res` (초과차폐) | +0.9209 | 0.2984 | 3.09 | 1.12 |
| log(길이) | +0.2767 | 0.1045 | 2.65 | 1.22 |
| 폭 | +0.0673 | 0.0083 | 8.12 | 1.23 |

**`w_s : w_t : w_v = 1 : 2.47 : 0.96`**. 잔차화 덕에 VIF 가 전부 1.6 미만이다.

**차폐는 DSI 의 억제변수이기도 하다.** 차폐를 빼면 `R_dsi` 계수가 +0.9583 → **+0.6328**
로 34% 줄고 비율이 1:3.75 가 된다. 도로폭과 같은 구조다 (D-05 · X-10).

**변경 영향은 작다.** 기존 `1:1.95:1.0` 대비 순위상관 **+0.9913**, 10위 이상 이동 1/75.

**한계**: 결과변수가 링크기반 위험지역이라 X-12 가 지적한 순환 문제가 그대로 있다. 이
가중치로 같은 자료를 예측해 성능을 주장하면 안 된다.

# §3. 실험 기록

## X-01. API `resultCode=10` 의 정체

문서에 없는 동작. **입력 세그먼트 중 하나라도 내부 세부링크에 매칭되지 않으면 요청 전체가
`10`** 이 된다. `03`(NODATA)이 아니라 파라미터 오류로 떨어진다.

실측 (강릉대로, 50m 간격 단독 조회):

```
seg[0]   0~ 50m  code=00 val=5.53  grd=2
seg[1]  50~100m  code=00 val=0.00  grd=1
seg[2] 100~150m  code=10   ← 이 구간이 섞이면 그 요청 전체가 실패
seg[3] 150~200m  code=00 val=0.22  grd=1
```

이 때문에 처음엔 "정점 6개 제한"으로 오독했다. 정점 수 제한이 아니고 실패 세그먼트의 포함
여부다 — 2점 500m 요청도 정상 동작한다.

→ 다중 세그먼트 요청은 실패 시 **이분 분할**해서 매칭 가능한 세그먼트만 건져야 한다.

## X-02. 차단·네트워크 실패가 결측으로 위장됐다

초기 `koroad_client.py` 는 `code != "00"` 을 전부 "세부링크 미매칭"으로 처리했다. 그 결과
**인증키 차단(`30`)과 네트워크 실패가 결측으로 위장되어 매칭률 통계가 오염**됐다.

간격 민감도 테스트에서 노선 A 가 대부분 0% 로 나온 것이 이 오염의 결과다. 허용량 소진 직후
에는 API 경로가 `connect timeout` 으로 응답조차 하지 않다가, 이후 `resultCode=30
SERVICE_KEY_IS_NOT_REGISTERED_ERROR` 로 바뀐다.

→ 현재 클라이언트는 `30`/네트워크 실패를 `QuotaError` 로 **즉시 중단**하고, `Client(budget=N)`
으로 실행당 호출 상한을 두며, `cli.codes` 에 resultCode 분포를 기록한다. 러너의 `save()` 는
빈 결과가 기존 파일을 덮어쓰지 못하게 막는다 (부록 A-01).

**허용량은 날짜가 바뀌면 초기화된다.** 별도 활용신청은 필요 없었다.

## X-03. 심각도 상관 — 귀무

| 검정 | 링크기반 (n=61) | 지자체별 (n=24) |
|---|---|---|
| 구역 평균 DSI | rho +0.126 (p=0.33) | rho −0.001 (p=1.00) |
| 구역 상위10% DSI | +0.198 (p=0.13) | +0.208 (p=0.33) |
| 등급·폭 통제 편상관 | +0.185 (p=0.15) | +0.393 (p=0.057) |
| 상·하위 절반 합산 (Fisher) | OR 1.153 (p=0.49) | OR 0.834 (p=0.51) |

링크기반은 전부 약한 양의 방향으로 일관되지만(0.13~0.20) 유의수준 근처도 아니다.

**지자체별의 p=0.057 은 믿을 게 못 된다.** 같은 데이터에서 통제 전 rho 가 −0.001 인데 통제 후
+0.393 으로 튀고, 합산 오즈비는 반대 방향(0.834)이다. n=24 에 공변량 둘을 넣은 결과이고,
검정을 10회 돌렸으니 전부 귀무여도 p<0.05 가 한 번 나올 확률이 40% 다.

**부수 발견**: 구역 상위10% DSI 가 두 데이터셋 모두에서 일관되게 가장 높은 rho 를 냈다.
"구역 평균이 아니라 최악 지점이 사고를 만든다"는 이론과 맞는다 → 주 검정 후보 (§0.2-B).

## X-04. 검정력 — 애초에 잡을 수 없는 크기였다

```
n=61  → |rho| ≥ 0.352 여야 80% 검정력
n=24  → |rho| ≥ 0.545
```

목표 상관별 필요 n: rho 0.15 → **347** / 0.20 → **194** / 0.25 → 124 / 0.30 → 85.
관측값 0.13~0.20 은 정확히 사각지대에 들어간다.

**세 가지가 겹쳤다.**

- **유사복제**: 64개 구역이 실제로는 서로 다른 장소 **36개**다(100m 기준). 같은 자리가 최대
  6개년 중복. 유효 n 은 36 에 가깝고, 보고된 p값은 그만큼 낙관적이다.
- **범위제한**: 전체 지점 DSI 는 SD 0.222(1.15~2.27)인데 구역 평균은 SD 0.099(1.17~1.53)로
  **44%** 로 깎였다. 평균을 내면서 한 번, 대상이 전부 도심권이라 또 한 번 줄었다.
- **분모 잡음**: 구역당 사고 중앙 9건. 심각도 비율의 이항 표준오차가 0.138 이다.

**기각한 대응** — 장소 단위 통합: n 61→36 으로 줄어드는데 분모 중앙값은 9 그대로다(반복
장소가 소수라 평균만 17 로 오름). 순손실. 사고 10건 이상 필터: n 61→28, rho 0.126→0.031.
잡음보다 신호를 더 많이 버린다.

폴백**이다. 좌표가 나오니 성공처럼 보이지만 실제 교차로와 무관하다. 건진 25개는 전부

## X-08. 보간 실패 ③ — 주요 링크만 남기면 도로망이 끊어진다

"자율주행 셔틀은 좁은 골목에 부적합하니 주요 링크로 커버리지를 줄이면 나아지지 않을까" 를
시험했다.

**커버리지는 실제로 크게 개선된다.** 주요 링크(등급 2·3, 1,110엣지 / 138km) 기준으로 계측점
500m 이내가 **992/1,110 (89%)**, 300m 이내 65%. 계측점에서 주요 링크까지 거리 중앙값이 38m.
**주요망에서는 보간할 일이 별로 없다.**

**그러나 중심성 계산은 불가능하다.** 어떤 정의를 써도 최대 연결성분이 13~15% 다.

| 정의 | 엣지 | 연장 | 최대성분 |
|---|---|---|---|
| 등급 ≤3 | 1,110 | 138 km | 15% |
| 폭 ≥8m | 2,826 | 254 km | 14% |
| 폭 ≥10m | 2,104 | 207 km | 15% |
| 등급≤3 또는 폭≥8m | 2,875 | 262 km | 13% |

간선끼리 직접 안 붙고 등급 4 도로를 거쳐 연결되기 때문이다. 축약하면 노드 91개짜리 파편만
남고, 주요망 중심성은 교통량과 rho +0.059 (p=0.63) · 단독 CV R² −0.067 로 무효다.

→ **중심성은 전체망에서 계산하고 값을 주요 링크에 붙여 쓴다.** 전체망 중심성은 rho +0.327 로
여전히 유용하다.

## X-09. 보간 실패 ④ — 표준노드링크도 링크 단위로는 무효

표준노드링크는 위상이 온전하다 — 노드 3,267개, 엣지 4,694개, **최대 연결성분 99.9%**.
`roads.geojson` 끝점이 최대 25m 어긋나(중앙 1.64m) 스냅으로는 위상이 안 서던 문제가 해결된다.

**그럼에도 속성이 교통량을 설명하지 못한다.**

| 변수 | 링크 단위 | **노드 단위** |
|---|---|---|
| 차로수 | +0.135 (p=0.25) | **+0.315 (p=0.006)** |
| 매개중심성 | +0.132 (p=0.26) | **+0.290 (p=0.012)** |
| 제한속도 | +0.146 (p=0.21) | +0.220 (p=0.059) |
| 도심거리 | — | −0.489 (p<0.001) |

링크 단위에서는 1차로 20,489대 vs 3차로 23,810대로 **거의 차이가 없다.** 노드 단위로 묶으면
단조 증가한다(차로수합 ≤3 → 17,647대, 8+ → 24,828대).

**진단: 교통량은 교차로 진입량이라 링크 속성이 아니다.** 한 링크에 스냅해 그 링크의 차로수로
설명하려 한 것이 오류였다.

노드 단위 최고 CV R² 은 **0.186** 으로 IDW(0.244)보다도 낮다. 상관이 유의해도 |rho| 0.3
수준이라 R² 로는 10% 남짓이고, n=74 에서 변수를 늘리면 곧바로 과적합한다(차로수+차수만
쓰면 R² 음수).

**참고**: `ROAD_RANK` 는 주요 링크 선별에 못 쓴다 — 강릉은 일반국도(103) 197개(6.6%),
시군도(107) 4,500개(93.4%) 로 사실상 두 종류뿐이다. 선별에는 `LANES` 를 써야 한다.

| 표본 / 교통량 출처 | n | OR | p |
|---|---|---|---|
| 500m 이내 · 실측 (주 추정치) | 3,688 | **1.223** | 0.0037 |
| 500m 이내 · IDW 보간 | 3,688 | 1.197 | 0.0078 |
| 전체 도로망 · IDW 보간 | 4,415 | 1.167 | 0.029 |
| 500m 밖만 · IDW 보간 | 727 | 1.042 | 0.88 |

같은 표본에서 실측과 보간의 차이가 0.026 뿐이다. **교통량-DSI 상관이 약해(rho 0.19) 통제변수
잡음이 새는 편향이 작기 때문**이다. 교통량을 아예 빼면 OR 이 1.269(500m)·1.247(전체)로
**오히려 커진다** — 교통량은 DSI 효과를 부풀리는 게 아니라 약간 눌러주는 방향이다.

**500m 밖 727개 엣지는 사실상 정보가 없다**(CI [0.60, 1.81]). 전체 도로망 결과는 500m 이내
구간이 끌고 간 값으로 봐야 한다.

**효과 크기** — DSI 1SD(0.208) 증가당 오즈 1.22배, 기저 17.1% 에서 20.1% 로. 같은 모형에서
log(교통량) 1단위당 **2.24배**다. 노출이 압도적이고 DSI 는 그 위에 얹히는 작은 항이다.

## X-11. 교통량 순위는 시간에 안정적이다

| 시차 | 순위상관 (Spearman) |
|---|---|
| 1개월 | 0.993 |
| 3개월 | 0.970 |
| 6개월 | 0.965 |

반기 평균끼리 rho 0.980, **사분위 2단계 이상 이동한 지점은 104개 중 0개**.

계절 진폭은 최대/최소 1.16배(8월 최고, 12월 최저). **반드시 온전한 12개월 주기로 평균낸다** —
부분 구간을 쓰면 계절 편향이 든다.

**한계**: 11개월 관측으로 9년 외삽을 정당화하는 것이다. 단기 무감쇠가 장기 무감쇠를 보장하지
않는다(신설 도로·개발). 현재 확보 가능한 최선의 근거일 뿐이다.

## X-12. AUC — 결합은 DSI 단독보다 낫지만 통행량 단독보다 낫지는 않다

교차로 150m 이내 사고지점 여부를 맞히는 AUC (부트스트랩 95% CI).

| 지수 | 지자체별 다발지역 (사례 8/75) | 링크기반 위험지역 (사례 28/75) |
|---|---|---|
| 정적 DSI 단독 | 0.459 [0.259, 0.673] | 0.601 [0.464, 0.735] |
| 정적 DSI 상위10% | 0.513 | 0.597 |
| **통행량 단독** | **0.756** [0.565, 0.911] | 0.663 [0.525, 0.793] |
| 차량차폐 단독 | 0.664 | 0.625 |
| CDI (DSI+통행량) | 0.688 [0.468, 0.866] | 0.669 [0.540, 0.785] |
| CDI (+차량차폐 w=1) | 0.705 | **0.679** [0.551, 0.802] |

**결합이 DSI 단독보다는 확실히 낫다**(0.459→0.688, 0.601→0.669). 그러나 **다발지역에서는
통행량 단독(0.756)이 결합(0.688)보다 높다** — DSI 를 섞으면 오히려 떨어진다.

신뢰구간이 전부 크게 겹쳐 어느 쪽이 낫다고 단정할 수 없다. **가중치를 링크기반에서 뽑아
링크기반으로 검증한 열(0.669)은 순환이라 독립 검증이 아니다.**

**해석**: 사고지점 예측만이 목적이라면 통행량만 쓰는 게 나을 수 있다. 결합의 근거는 예측력이
아니라 **목적이 다르다**는 데 있다 — 사고 이력이 없는 구간도 사전 진단하는 것이 DSI 의
취지이고 통행량은 그걸 못 한다. 이 표는 "결합이 예측을 개선한다"가 아니라 **"결합해도
예측력이 유지되면서 사전 진단 능력이 더해진다"** 로 써야 한다.

**부수 결과**: 결합은 순위를 실제로 바꾼다. 정적 DSI 단독 순위와의 상관 0.612, **75개 중
50개가 10위 이상 이동**. 예: `교동사거리` DSI 23위 → 통행량 8위 → 종합 8위.
`강릉교사거리` DSI 38위 → 통행량 5위 → 종합 9위.

## X-13. 반경 선택 — 신뢰도 기준은 실패했고 감쇠 프로파일이 답을 줬다

### 기각된 기준 — 집계 신뢰도의 최댓값

"반경이 작으면 표본이 적어 잡음, 크면 진입로·다음 블록까지 평균해 교차로 간 분산이
무너지므로 유한한 r 에서 최대가 된다"는 설계였다. ICC 계열로 정의했다.

```
reliability = (var_between - mean(var_within / n)) / var_between
```

**30m→300m 에서 0.826 → 0.986 으로 단조증가했다. 최댓값이 없다.**

원인은 `var_between` 이 어느 반경에서도 0.09 로 평평하다는 것이다. 300m 까지 평균해도 DSI 장의
공간구조가 씻기지 않는다. 그러면 남는 것은 `1/n` 뿐이라 반경이 클수록 좋아지는 양이 된다.
**애초에 최댓값을 갖도록 설계된 통계량이 아니었다.** `composite/radius_sweep.py` 에 기록으로 남긴다.

### 채택된 기준 — 방사 감쇠 프로파일

각 DSI 지점을 **최근접 교차로에만** 배정해(중복계산 없음) 거리대별 평균을 냈다. 배경은
400~600m 대(n=6,420), CI 는 교차로 단위 군집 부트스트랩 400회. `composite/radius_profile.py`.

**발견 ① — DSI 는 교차로 근처가 오히려 낮다.**

0~25m 에서 1.2485, 배경 1.3458 → **−0.0973 (정적 DSI 1SD 의 0.47배, 부호는 음)**. 거리와 함께
단조 상승해 100m 에서 배경과 만난다. 225~350m 에서는 되레 유의하게 높다(+0.036~+0.047) —
간선 사이 이면도로 띠로 보이며, 위 `var_between` 이 안 씻긴 이유이기도 하다.

X-06 · D-05 와 결이 같다. DSI 는 넓고 트인 간선을 안전하게 평가하고 계측 교차로 75개는 전부
그 위에 있다. **CDI 의 DSI 항은 구조적으로 안전한 쪽에 몰린 부분집합 안에서 순위를 매기고
있다.** 순위 기반이라 수준 효과는 흡수되지만 범위 제한은 남는다 (X-04 와 같은 계열의 제약).

**발견 ② — 차량 차폐는 깨끗한 교차로 중심 감쇠다.**

0~25m 에서 배경(0.0455) 대비 **+130%**. 최대치의 50% 도달 150m, 25% 250m, 10% 350m.
DSI 와 달리 교차로 중심 영향권이 실재한다. 75m 는 이 봉우리의 대부분을 담는다.

### 반경별 요약

| 반경 | DSI 고유신호 | 중첩 | 공유점 | 교차로 | 차폐 SD | 신뢰도(유효n) |
|---:|:--|---:|---:|---:|---:|---:|
| 50m | 유의 | 3% | 0% | 73/75 | 0.0522 | 0.774 |
| 60m | 유의 | 3% | 0.4% | 75/75 | 0.0498 | 0.790 |
| **75m** | **유의 (마지막)** | **5%** | **0.6%** | **75/75** | **0.0452** | **0.819** |
| 100m | 사라짐 | 13% | 1.3% | 75/75 | 0.0430 | 0.849 |
| 150m | — | 43% | 4.6% | 75/75 | 0.0385 | 0.905 |
| 300m | — | 85% | 33% | 75/75 | 0.0318 | 0.969 |

차폐 SD(교차로 간 대비)는 반경이 작을수록 커진다. 신뢰도만 홀로 반대를 가리킨다.

### 곁가지 — X-12 가 낡았다

AUC 표는 **100m 영향권**과 **오류 좌표**(A-06)로 계산됐다. 두 조건이 다 바뀌었으므로 현재
산출물과 나란히 인용하면 안 된다. 게다가 **계산 스크립트가 남아 있지 않다** — 임시 실행이었고
`analysis/` 어디에도 AUC 코드가 없다. 재산출하려면 다시 짜야 한다 (§0.2).

## X-14. 차량차폐가 통행량과 얼마나 겹치는가 — 분리 시도는 실패했다

D-08 은 "통행량과 상관될 수밖에 없다" 고만 적었다. 규모를 재보니 작지 않다.

### 겹침의 크기 (교차로 n=75, 반경 75m)

| 관계 | rho | p |
|---|---:|---:|
| **차량차폐 ~ 통행량** | **+0.496** | 0.0000 |
| 도로폭 통제 후 | +0.476 | 0.0000 |
| 차량차폐 ~ DSI | +0.197 | 0.090 |
| DSI ~ 통행량 | +0.262 | 0.023 |

공유분산 **24.6%**. **중복이지만 대체는 아니다** — 나머지 75% 는 통행량이 아니다.
도로폭을 통제해도 거의 안 줄어드는 것이 중요하다. 폭은 매개 경로가 아니다.

### 방향이 주정차와 반대다 (지점 n=34,724)

`veh_extra_occ ~ 도로폭` **rho +0.302**. 불법주정차라면 좁은 상업가에 몰려야 하는데
넓은 길에 더 많다. **주행 차량처럼 행동한다.**

| 도로폭 | n | 구조물차폐 | 추가차폐 | 여유공간 | 추가/여유 |
|---|---:|---:|---:|---:|---:|
| ~6m | 11,982 | 0.2240 | 0.0315 | 0.7760 | **0.0406** |
| 6~10 | 10,774 | 0.2224 | 0.0716 | 0.7776 | 0.0921 |
| 10~15 | 5,379 | 0.0821 | 0.0705 | 0.9179 | 0.0768 |
| 15~20 | 738 | 0.1224 | 0.0911 | 0.8776 | 0.1038 |
| 20m~ | 5,851 | 0.0782 | 0.0759 | 0.9218 | 0.0823 |

**천장효과는 배제했다.** "좁은 길은 이미 구조물로 막혀 차량이 더할 여지가 없다" 를 의심해
여유공간(1−구조물차폐) 대비로 보정했으나 `~6m` 가 여전히 최저다. 좁은 골목에 차량 차폐가
정말 적다. 단조 증가가 아니라 **6m 부근의 문턱**이고 그 위로는 평평하다.

### 기각 — fwd/bwd 비대칭으로 주정차를 분리하려던 시도

노변 주차는 한쪽만 가리고 주행 차량은 양쪽을 가릴 것으로 보아 `veh_blocked_fwd` /
`veh_blocked_bwd` 의 비대칭을 주정차 특이 신호로 쓰려 했다. (실측 분포: 한쪽만 57.8%,
양쪽 27.2%)

| 지표 | ~통행량 | ~도로폭 |
|---|---:|---:|
| 차량차폐 (현행) | +0.496 | +0.302 |
| 한쪽만 막힘 비율 | **+0.382** | +0.145 |
| 양쪽 막힘 비율 | +0.433 | +0.082 |

비대칭 지표도 통행량과 **+0.382** 다. 분리되지 않는다. **파이프라인 산출물 안에 주정차
특이적 신호는 없다.** 더 나은 대리변수를 찾는 대신 잔차화로 간다 (D-13).

## X-15. `w_v` 유도 — 두 경로가 수렴하지 않았다

불법주정차 실측이 없으니 검증은 불가능하다. 대신 **서로 독립인 두 경로**로 유도해 비교했다.

### 경로 ① 빈도모형 계수비 (D-07 을 순위 척도로 확장)

모형에 `log(교통량)` 이 들어 있으므로 차폐 계수는 **통행량을 통제한 부분효과**다 —
D-13 이 요구하는 조건과 일치한다. FWL 정리대로 원지표를 넣든 잔차를 넣든 차폐 계수는
거의 같다 (+0.9338 vs +0.9209).

| 모형 | `w_s : w_t : w_v` |
|---|---|
| A 차폐 없음 | 1 : 3.75 : — |
| B 차폐 원지표 | 1 : 2.29 : 0.98 |
| **C 초과차폐 (채택)** | **1 : 2.47 : 0.96** |

### 경로 ② 파이프라인 내부 탄력도

파이프라인은 이미 `dsi_veh`(차량 차폐를 포함한 DSI)를 계산한다. 즉 차폐를 구조적 위험
대비 얼마로 칠지에 대한 **내부 답**을 갖고 있다. 순위 척도로 읽으면 (n=34,724):

```
rank(dsi_veh) = -0.133 + 0.904·rank(DSI) + 0.363·rank(차폐)
```

**`w_v / w_s = 0.40`**.

### 수렴하지 않는다 — 그래서 구간으로 제시한다

**0.96 (빈도모형) vs 0.40 (파이프라인 내부).** 2.4배 차이다. 둘은 다른 질문에 답하므로
어느 쪽이 옳다고 할 근거가 없다 — ①은 "사고 이력과의 연관", ②는 "파이프라인이 스스로
매기는 비중"이다. **`w_v = 0.40 ~ 0.96` 구간으로 제시한다.** §0.2 의 "단일값이냐 구간이냐"
는 이로써 결정이 아니라 **결과**가 됐다.

### 다행히 실질 영향은 작다

`w_s : w_t = 1 : 2.47` 고정, `w_v` 를 구간 안에서 움직였을 때 (기준 0.40):

| `w_v` | 순위상관 | 10위 이상 이동 |
|---:|---:|---:|
| 0.70 | +0.9950 | 0/75 |
| 0.96 | +0.9834 | 1/75 |

**구간의 폭이 순위를 거의 바꾸지 않는다.** 수렴 실패가 결론을 흔들지는 않는다.
출력에는 `cdi_0.0`(시나리오 없음) · `cdi_0.4` · `cdi_0.7` · `cdi_0.96` 을 병기한다.

`data/traffic_points_geocoded.csv`(Nominatim 판)는 **생성 스크립트가 없다.** 이전 정리 때

`statsmodels` 없이 numpy/scipy 로 구현했다 — 로지스틱은 IRLS, 표준오차는 샌드위치,

## 4.2 xlsx 읽기 — openpyxl 없이

# 부록 A. 이 작업에서 낸 결함과 수정

## A-01. 수집분을 빈 결과로 덮어썼다

`run_bus_routes.py` 가 `QuotaError` 로 중단된 뒤 `res={}` 상태로 `json.dump` 를 실행해
`bus_routes_dgdgr.json` 을 `{}` 로 덮어썼다. **셔틀 노선 A/B/C 세그먼트 원자료가 유실**됐고
요약 수치만 남았다.

→ 러너에 `save()` 를 넣어 빈 결과일 때 파일을 건드리지 않고, 기존 파일이 더 완전하면
`*_partial.json` 으로 분리 저장한다.

## A-02. 격자 반올림으로 반복 지점을 과소 집계했다

100m *격자* 반올림(`round(lon*900)`)으로 반복 출현을 세다가 격자 경계에 걸친 지점이 쪼개져
**옥천오거리 5개년 · 강릉역육거리 3개년**으로 보고했다. 실제는 좌표 거리 기반 군집으로
**7개년 · 4개년**이다. 같은 원인으로 `금학동1021`(1개년)이 2개년으로 잘못 묶였다.

→ D-11 로 단일연결 군집 확정.

## A-03. 이름 매칭이 엉뚱한 지점을 붙였다

`솔올교차로`·`터미널오거리`가 목록에 따로 있는데도 정규화 과정에서 `교차로`를 지워
`솔올중학교부근`, `주문진터미널오거리`(20km 밖)에 매칭했다.

→ 정확 매칭 우선, 부분 매칭은 `△` 로 표시해 사람이 확인하도록 분리.

## A-04. 800m 확장 검증이 공회전했다

`freq_edges_500m.csv` 가 이미 500m 로 걸러진 파일인데 거기서 `tp_dist <= 800` 을 걸어
"800m 이내"를 계산했다. 500m 결과와 같은 값이 나온 것은 확장이 재현된 게 아니라 **같은
데이터였기 때문**이다. IDW 판(X-10)에서 도로망 전체로 다시 확인했다.

## A-05. 그래프를 잘못 만들어 중심성이 전부 0 이었다

`roads.geojson` 끝점을 1m 로 스냅해 그래프를 만들었으나 실제 끝점 간격이 중앙 1.64m ·
90분위 25m 라 **최대 연결성분이 노드 9개**였다. 4,566개 엣지 중 4,558개의 중심성이 0 이
나왔는데 그대로 회귀에 넣었다.

→ 위상이 명시된 `road_graph.npz`(차수 2 사슬 축약)로 교체. 이후 표준노드링크로 다시 교체.

## A-06. 지오코딩 결과에 중복 좌표 검사를 하지 않았다

`교동사거리`(cid 10)와 `선수촌삼거리`(cid 236)가 **주소가 같아**(`홍제동 666-10`) 동일 좌표로
지오코딩됐다. 원본 xlsx 의 오류지만, 검사를 안 해 그대로 통과시켰다.

두 교차로가 영향권을 공유해 `dsi` · `veh_occ` 가 완전히 같고 AADT 만 다른 상태로 결합 지수에
들어갔다 — 독립 관측이 아니었다. 하필 `교동사거리` 가 X-12 의 대표 사례(DSI 23위 → 종합 8위)로
인용된 항목이다.

실제 주소는 `교동 980-1`, **강릉대로(3차로) × 임영로 사거리**다. 표준노드링크에서 교차로 코너
노드 4개(`2520012301`~`04`)로 확인했다. 기존 좌표에서 **2,320m** 떨어져 있었다.

→ `prep/geocode.py` 에 `ADDR_FIX` 보정표를 뒀다. 원본 xlsx 를 매번 다시 읽는 구조라 CSV 만
고치면 재실행 때 사라진다. **지오코딩 후 중복 좌표 검사를 절차에 넣을 것.**
