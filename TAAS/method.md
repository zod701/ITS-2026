**지금 가장 큰 문제는 DSI 가 어떤 사고 결과와도 양의 연관이 확인되지 않았다는 것이다.**
원시 사고지점(2024~25 중상 이상 216건)으로 재유도하자 전체 사고 기준 **DSI 계수가 음수**
(−0.959, 95% CI [−2.29, +0.20])로 나왔다 (X-25).

**다만 그 음수는 전체가 아니라 한 유형에 국한된다** (X-26). 하위유형으로 쪼개면

| 하위집합 | `R_dsi` | z |
|---|---:|---:|
| 차대차 × 교차로 | **−3.098** | −3.35 |
| 차대차 | −2.454 | −3.35 |
| **차대사람** | **+0.198** | 0.30 |
| 단일로 | +0.081 | 0.09 |

**음수는 전부 차대차에서 나온다.** 넓은 간선 교차로에서 나는 차대차 사고의 기전(속도·신호·
좌회전 상충)에 시야 차폐가 없고, DSI 는 그런 곳을 낮게 평가하므로 음의 상관이 생긴다 —
**교란이지 인과가 아니다.** 보행자 사고에서는 음수가 사라진다. 다만 **양수도 아니다**(z=0.30):
관계가 있다는 근거도 없다. 정확한 서술은 **"판별 불가"** 다.

**반면 파이프라인의 차폐 산출물은 강하게 양이다** — 보행자 사고에 `R_res +1.781 (z 4.57)`,
단일로 보행자만 보면 `+2.050`. 자율주행차가 가장 취약한 실패 모드(가려진 곳에서 나오는 보행자)에
대해 **파이프라인의 핵심 측정이 실제 사고와 연결된다는 직접 증거**다. 결합 지수 전체가 아니라
이 부분이 현재 가장 잘 뒷받침되는 결과다.

`α` 를 사고 자료로 유도하지 않는 결정(D-21)은 유지한다. 근거가 "DSI 는 다른 실패 모드를
잰다"였는데, X-26 이 그 주장을 **부분적으로 지지**한다 — 음수가 차대차에 국한된다는 점에서.
그러나 보행자 사고에 대한 양의 근거는 없으므로 여전히 **검증되지 않은 해석**이다.

`β = 0.398` 은 확정했다 (D-20). 통행량 +0.929 · 초과차폐 +1.409 로 **주정차 대리가 통행량보다
크다.** 절단 자료의 0.720 이 통행량을 부풀리고 있었다는 X-24 의 예측이 맞았다 — 새 β 가 0.720
이상일 확률은 부트스트랩에서 0.1% 다.

**산출 단위는 링크로 확정했다** (D-17). 교차로 진입량을 차수로 나눠 링크 몫으로 근사한 뒤 IDW 로
보간하고, 링크마다 `data_source` 신뢰도 플래그를 단다. **예측이 아니라 결합 구조의 개념검증(PoC)**
이며 성능은 낮다 — LOO R² **+0.123**, 배수오차 중앙 1.42. 동적 항의 **91.7% 가 보간값**이다.
D-15 의 기각 근거(예측 천장)는 그대로 유효하고, D-17 은 그 결론을 뒤집는 것이 아니라 **목적을
예측에서 시연으로 바꾼** 것이다. 이 수치를 예측 성능으로 인용하면 안 된다 (§4.3).

같은 방법을 지점 단위로 적용해 웹 버전 `260820_2` 를 냈다 (D-18). 정적 DSI 만으로는 노선 A/B/C
가 1.203~1.234 로 구분되지 않았는데, 동적을 결합하니 **A 0.4385 vs B 0.2256 으로 갈린다.**
다만 A 가 높은 이유의 일부는 A 가 계측 교차로를 17개 지나기 때문이다(B 1개, C 3개) — 실제
통행량과 **측정 밀도가 섞여 있다** (X-21).

교통량을 링크나 미계측 교차로로 넓히려는 시도는 **여섯 번 전부 실패했고 천장이 특정됐다**
(D-15 · X-16~X-18). 동적 지수로 쓰려던 차량 차폐도 **평일 08~16시 단일 관측**이라 시간
변동을 대표하지 못한다 (D-16 · X-19).

검정력 문제(X-04)는 해소되지 않았으나 우선순위에서 내려갔다. 심각도 분석의 n 이 61(실제 서로
다른 장소는 36)이라 관측된 상관 0.13~0.20 을 잡으려면 n≈194 가 필요하다. **강한 상관은
배제했고 약한 상관은 판별할 수 없다** — 이 문장 이상을 주장하면 과잉해석이다.

## 1.2 핵심 수식

**결합 위험지수 (CDI)** — 교차로 단위

```
CDI = (w_s·R_dsi + w_t·R_aadt + w_v·R_resid) / (w_s + w_t + w_v)

  R_x     = 백분위 순위(0~1)  ; 분포 가정 없이 척도를 맞추기 위함
  R_resid = 순위(R_veh − R_aadt 로 예측한 R_veh)
                             ; 통행량 성분을 뺀 "초과차폐" (D-13)
  w_s : w_t : w_v = 1 : 2.47 : 0.40~0.96
                             ; 빈도모형 계수비, **순위 척도** 추정 (D-14)
                             ; w_v 는 두 유도 경로가 수렴하지 않아 구간 (X-15)
  ★ R_veh 원지표를 쓰면 통행량을 두 번 센다 (rho +0.496, 공유분산 24.6%)
```

**링크 동적 지수 (PoC)** — 표준노드링크 링크 단위, D-17

```
1단계  V_adj(i)   = 진입량(i) / 차수(i)              ; 교차로 -> 링크 몫 근사
2단계  V_link(e)  = Σ w·V_adj / Σ w,  w = 1/d^p     ; IDW k=5, p=1, 링크 중점 기준
3단계  V_norm(e)  = minmax(clip(V_link, 1%, 99%))
4단계  DSI_dyn(e) = β·V_norm + (1-β)·P_resid        ; β = 0.398   (D-20)
       DSI_t(e)   = α·DSI_static + (1-α)·DSI_dyn    ; α = 0.20/0.35/0.50 (D-21)
  β  원시 사고지점 포아송 계수비 0.929 : 1.409 에서 유도 (X-25)
  α  자료로 유도되지 않는다 — 같은 모형에서 DSI 계수가 음수다. **설계 시나리오**
  ★ 정규화 기준점은 **기준판(평시 260820_2)의 것을 모든 판이 공유**한다 (D-24).
    판마다 따로 정규화하면 이벤트판의 수준 상승이 상쇄되어 비교가 성립하지 않는다.
    기준판만 상하위 1% 클리핑을 하고, 다른 판은 **선형 변환만** 적용한다 —
    기준판 상한으로 자르면 축제의 초과분이 잘려 나간다. 그래서 이벤트판의
    V_norm 은 1 을 넘을 수 있고, 그것이 '평시 최대보다 통행량이 많다'를 뜻한다.
  P_resid = 주정차 대리에서 통행량 성분을 뺀 잔차 (D-13). 통행량 항이 옆에 있으므로
            원지표를 쓰면 이중계산이고, β·α 가 잔차 전제로 유도된 부분계수라 전제도 깨진다
  ★ 정적DSI만 / 정적DSI없음 플래그 링크는 DSI_t = DSI_static 으로 둔다
```

**빈도모형** — 엣지 단위, 계측점 500m 이내

```
logit P(사고위험지역과 교차) = β0 + β1·z(DSI) + β2·log(길이) + β3·log(교통량) + β4·폭
  표준오차 : 최근접 계측점 군집 강건 + 와일드 군집 부트스트랩 (Rademacher, 제약 귀무)
  ★ 도로등급은 넣지 않는다 (D-04)
```

**심각도** — 구역 단위

```
심각도 = (총사망자수 + 총중상자수) / 총사고건수
```

# §2. 결정 기록

## D-01. 세부링크 도로위험지수 API 는 정적 DSI 검증에 쓰지 않는다

`opendata.koroad.or.kr/data/rest/road/dgdgr/link` 는 **실시간 5분 주기** 지표다. DSI 는 촬영일
교통과 무관한 구조적 속성이므로 성질이 다르다. 같은 구간을 여러 시각에 반복 수집해 평균을
내면 시점 편차는 줄일 수 있으나 호출 수가 배로 든다.

여기에 커버리지 문제가 겹친다 — 미매칭 구간이 절반 가까워(주요 시내 도로 172/302 세그먼트,
57%) 노선 전체 비교가 아니라 매칭된 구간만의 부분 비교가 된다. **구도심 이면도로에서 특히
비어 있는데, DSI 가 높게 나오는 곳도 주로 이런 구간이라 하필 겹친다.**

→ 수집 코드(`koroad_client.py`, `run_bus_routes.py`, `run_gangneung_bus.py`)와 수집분
(`gangneung_bus_dgdgr.json`)은 보존하되 본 분석에서는 쓰지 않는다. 참조: X-01 · X-02.

## D-02. 포털 CSV 가 API 를 전량 대체한다

강릉 64건의 `사고위험지역id` 가 API 수집분과 **완전 일치**했다. 연도별 건수·사고수는 물론
2023년만 `51150`(강원특별자치도)이고 나머지는 `42150`(강원도)인 코드 불일치까지 동일하다.

CSV 가 나은 점 — 전국 전 연도 일괄 / 허용량·페이징·차단 없음 / 시도코드 분기 불필요.

**함정: 법정동코드 전환 시점이 데이터셋마다 다르다.**

| 데이터셋 | 42 / 4215 | 51 / 5115 |
|---|---|---|
| 링크기반 교통사고 위험지역 | 2017~2022, **2024, 2025** | **2023만** |
| 지자체별 교통사고 다발지역 | 2018~2023 | 2024, 2025 |

한쪽 규칙을 다른 쪽에 적용하면 **에러 없이 빈 결과**가 나온다. `startswith(('4215','5115'))`
처럼 양쪽을 받아야 한다.

원본 헤더 오타도 있다 — 링크기반 CSV 의 총사고건수 컬럼명이 **`츙사고건수`** 다.

## D-03. 심각도 결과변수는 `(사망+중상)/사고건수`

사고 건수는 교통량에 비례하므로 노출 통제 없이는 해석할 수 없다. 반면 **사고가 났다는 조건
하의 심각도 비율은 노출도가 상당 부분 약분된다.** 이론적으로도 맞다 — 시야 차폐는 발견을
늦춰 충돌속도를 올리므로 빈도보다 심각도에 먼저 나타나야 한다.

대가는 표본이다. 지점 3.4만 개는 DSI 집계에만 쓰이고 검정의 n 은 구역 수(61)로 떨어진다.
대신 유사독립이 확보돼 p값이 의미를 갖는다. 결과는 X-03 — 귀무.

## D-04. 도로등급을 통제변수로 쓰지 않는다

측정 결과 **도로등급과 DSI 의 Spearman rho 가 +0.633** 이다. 통제하면 DSI 분산의 40% 가 함께
사라진다. 교란변수이면서 동시에 관심변수의 대리라서, 통제하면 과소추정 쪽으로 편향된다.

해상도도 부족하다 — 강릉시내 2,664개 도로구간이 등급 3개로만 나뉘고 **2,218개(83%)가 같은
등급 4** 다. 같은 등급 안에서 강릉대로와 한적한 이면도로가 한 칸에 들어간다.

**교통량은 DSI 와 rho +0.188 이라 통제해도 DSI 분산의 96% 가 남는다.** 노출 통제변수로서
이상적인 성질이다 — 결과와는 연관되고 관심변수와는 거의 무관하다. 교통량 확보의 실질적
가치가 여기에 있다.

## D-05. 도로폭은 통제한다 — 억제변수이기 때문

도로폭을 넣기 전과 후로 결과가 뒤집힌다.

| 모형 | OR (DSI 1SD) | p |
|---|---|---|
| 길이 + 교통량 | 0.984 | 0.83 |
| **+ 도로폭** | **1.226** | 0.0037 |
| + 계측점거리만 | 1.015 | 0.85 |

우연이나 사후선택이 아니라 **억제(suppression)** 구조다.

- 도로폭 ↔ DSI: rho **−0.376** (넓을수록 트여 DSI 낮음)
- 도로폭 ↔ 사례: rho **+0.123** (넓을수록 사고밀집 확률 높음)

폭이 DSI 를 끌어내리면서 동시에 사고를 끌어올리니, 통제하지 않으면 두 경로가 상쇄돼 DSI 가
무효로 보인다. 계측점거리는 단독 투입 시 무영향(1.015)이라, 이 효과가 거리 통제로 만들어진
인공물이 아님도 확인됐다. 상세: X-10.

**주장 문장에는 반드시 조건이 붙어야 한다** — "같은 도로폭·같은 교통량에서". 무조건부로는
효과가 0 에 가깝다.

## D-06. 교통량은 교차로 단위로만 쓴다

링크 보간을 **네 가지 방식으로 시도해 전부 실패**했다 (X-07 · X-08 · X-09).

| 방식 | 최고 성능 | 배수오차 중앙 |
|---|---|---|
| 전체망 중심성 + 폭·등급·도심거리 회귀 | CV R² 0.185 | 1.38배 |
| 주요망 한정 | CV R² 0.203 | 1.37배 |
| 공간 IDW (최근접 3개) | LOO R² 0.244 | 1.38배 |
| 표준노드링크 노드 단위 | CV R² 0.186 | 1.35배 |

**근본 원인은 관측 단위 불일치다.** 교통량 자료는 *교차로 진입량*이지 링크 통과량이 아니다.
한 링크에 스냅해 그 링크의 차로수로 설명하려는 시도 자체가 무리였다. 노드 단위로 옮기면
상관은 살아나지만(X-09) 예측 성능은 여전히 부족하다.

→ 자료의 원래 단위를 지킨다. 결합 지수는 교차로에서만 산출하고, 구간(링크)은 DSI 단독으로
평가하는 **이원 구조**로 간다.

**시점**: 교통량은 2025-08~2026-07, 사고는 2017~2025 로 어긋난다. 그러나 노출 통제에 필요한
것은 절대 교통량이 아니라 **교차로 간 상대 순위**이고, 그 순위는 시차가 늘어도 무너지지
않는다(X-11). 2024-09 자료로 내려가면 11개월을 앞당기는 대신 계측점이 104 → 80개로 23%
줄어든다 — 9년 격차에서 11개월은 무의미하고 커버리지 손실은 즉각적이다. **최신 자료를 쓴다.**

## D-07. 결합 가중치는 빈도모형 계수비에서 유도한다

임의 가중치를 피한다. 빈도모형(n=3,688)의 계수를 같은 1SD 단위로 환산한다.

```
DSI 1SD(=0.2078) 당 계수        +0.2013     (OR 1.223)
log교통량 1단위 당 계수          +0.8065     (OR 2.24)
log교통량 1SD(교차로, 0.4876) 당  +0.3932

→ DSI : 통행량 = 1 : 1.95
```

"동적 조건이 구조적 안전보다 크게 작용할 수 있다"는 가설이 이 비율에 수치로 들어가 있다.

**한계**: 이 계수는 링크기반 위험지역을 결과로 삼은 모형에서 나왔다. 다른 결과변수(심각도,
실제 사고율)에서는 비율이 달라질 수 있다. 가중치를 바꿔 민감도를 함께 제시해야 한다.

## D-12. 결합 영향권 반경은 75m

세 기준이 모두 100m 보다 작은 쪽을 가리킨다. 근거 실험은 X-13.

**① 구성타당도 — 결정적 기준.** 교차로 주변 DSI 를 배경(400~600m)과 비교하면

| 거리대 | 배경 대비 초과 | 95% CI (군집 부트스트랩) |
|---|---:|---|
| 0~25m | −0.0973 | [−0.123, −0.070] |
| 25~50m | −0.0575 | [−0.081, −0.030] |
| 50~75m | −0.0306 | [−0.058, −0.004] |
| **75~100m** | −0.0090 | **[−0.041, +0.023]** ← 배경과 구분 안 됨 |

75m 까지가 교차로 고유 신호다. **100m 를 넘으면 "이 교차로"가 아니라 "이 동네"를 재게 된다.**

**② 기하 — 이웃과의 중첩.** 계측 교차로 최근접이웃 거리는 중앙 338m · p05 173m.
영향권이 이웃과 겹치는 교차로 비율이 75m 5% → 100m 13% → 150m 43% 로 급증한다.

**③ 표본 확보.** 60m 부터 교차로 75개가 전부 `n_pt >= 5` 를 만족한다 (50m 73개, 30m 62개).

**반대를 가리키는 기준 하나는 기각했다.** 집계평균의 신뢰도만은 반경이 클수록 좋아진다
(유효n 기준 75m 0.819 → 100m 0.849). 이득 +0.030 에 중첩 2.5배는 치를 값이 아니다.

**이 결정의 영향은 작다.** 100m 대비 CDI 순위상관 **+0.982**, 10위 이상 이동 3/75,
상위 10 중 9개 유지. 방어 가능한 선택이되 결과를 뒤집지 않는다. 크게 움직이는 것은 DSI 항
단독(rho +0.900, 21/75 이동)이고 CDI 에서는 통행량 항이 그 흔들림을 잡아준다.

**D-11 의 100m 와는 다른 파라미터다.** 그쪽은 반복 지점 군집 임계값이다. 같이 움직이지 않는다.

## D-13. 동적 2번 항은 차량차폐 원지표가 아니라 통행량 잔차

D-08 에서 "두 동적 지수가 독립이 아니다" 라고만 적어둔 것을 실제로 쟀다. 겹친다 (X-14).

- 차량차폐 ~ 통행량 rho **+0.496**, 공유분산 **24.6%**
- 도로폭을 통제해도 **+0.476** — 폭이 매개가 아니다
- 원지표를 그대로 쓰면 통행량이 1번과 2번 항에 나뉘어 들어가 **두 번 세어진다**

**조치**: 2번 항을 통행량 회귀의 잔차로 바꾼다.

```
초과차폐 = R_veh - (R_aadt 로 예측한 R_veh)
```

| 항 | 통행량과의 rho |
|---|---:|
| 차폐(원지표) | +0.496 |
| 통행량몫 — 버리는 성분 | +1.000 |
| **초과차폐 — 2번 항** | **+0.049** |

분해는 완전하다(잔차 오차 2.8e-17). 버리는 성분은 **1번 항이 이미 100% 담고 있으므로
정보 손실이 아니라 중복 제거**다. 항은 여전히 셋이고 통행량은 1번에만 나타난다.

**이름도 바꾼다.** `차량 점유로 인한 추가 차폐` → **`통행량으로 설명되지 않는 추가 차폐`**.
불법주정차 대리로는 이쪽이 맞다. D-08 의 명명 주의(주차·정차·주행 미구분, 스냅샷 1회)는
그대로 유효하다.

**지수 값에는 거의 영향이 없다.** 원지표판과 순위상관 **+0.990**, 10위 이상 이동 **0/75**.
순위를 바꾸려는 조치가 아니라 **해석의 정당성을 위한 조치**다. 다만 시나리오 효과는 읽기
쉬워졌다 — `장안교차로`(통행량 하위 5%, 초과차폐 상위 1%), `경포초사거리`(하위 21%,
상위 0%)처럼 통행량으로 설명되지 않는 곳만 올라온다.

**가중치 유도의 전제가 된다.** 결합모형에서 뽑는 계수는 상대를 통제한 부분효과다. 그
부분계수를 서로 상관된 원지표에 곱하면 겹치는 24.6% 를 다시 두 번 센다. **잔차화된 입력과
부분가중치는 세트로만 성립한다.** `w_v` 의 단위도 "차폐 1단위당" 이 아니라 **"초과차폐
1단위당"** 이므로 유도를 같은 조건에서 해야 한다.

**한계**: 순위 위 **선형** 분해다. 관계가 비선형이면 통행량이 조금 샌다 (측정된 누수 +0.049).

## D-14. 가중치는 순위 척도에서 유도한다 — D-07 의 SD 환산을 대체

**D-07 의 `1 : 1.95` 는 척도가 섞인 값이었다.** SD 를 어느 단위에서 취하느냐로 비율이 흔들린다.

| SD 출처 | `w_s : w_t` |
|---|---|
| 엣지로 통일 | 1 : 1.85 |
| 교차로로 통일 | 1 : **4.49** |
| D-07 (DSI 는 엣지, 교통량은 교차로) | 1 : 1.95 |

DSI 는 영향권 평균을 내면 SD 가 **0.208 → 0.091** 로 줄고 교통량은 교차로에서 직접
재므로 안 줄어든다. 그래서 어느 단위를 쓰느냐가 2.4배 차이를 만든다.

**해법 — 지수가 쓰는 척도에서 바로 추정한다.** CDI 는 백분위 순위로 결합한다. 그러면
예측변수도 순위로 넣어 계수를 읽으면 된다. 순위는 어느 단위에서 매기든 균등분포라
**환산 자체가 없어진다.**

빈도모형(엣지 n=3,706, 사례 647, 계측점 75군집 강건 SE):

| 항 | 계수 | SE | z | VIF |
|---|---:|---:|---:|---:|
| `R_dsi` | +0.9583 | 0.3286 | 2.92 | 1.53 |
| `R_aadt` | +2.3654 | 0.8248 | 2.87 | 1.06 |
| `R_res` (초과차폐) | +0.9209 | 0.2984 | 3.09 | 1.12 |
| log(길이) | +0.2767 | 0.1045 | 2.65 | 1.22 |
| 폭 | +0.0673 | 0.0083 | 8.12 | 1.23 |

**`w_s : w_t : w_v = 1 : 2.47 : 0.96`**. 잔차화 덕에 VIF 가 전부 1.6 미만이다.

**차폐는 DSI 의 억제변수이기도 하다.** 차폐를 빼면 `R_dsi` 계수가 +0.9583 → **+0.6328**
로 34% 줄고 비율이 1:3.75 가 된다. 도로폭과 같은 구조다 (D-05 · X-10).

**변경 영향은 작다.** 기존 `1:1.95:1.0` 대비 순위상관 **+0.9913**, 10위 이상 이동 1/75.

**한계**: 결과변수가 링크기반 위험지역이라 X-12 가 지적한 순환 문제가 그대로 있다. 이
가중치로 같은 자료를 예측해 성능을 주장하면 안 된다.

## D-15. 교통량의 공간 확장을 종료한다

계측 교차로 68개의 값을 링크나 미계측 교차로로 넓히려는 시도를 **여섯 번 했고 전부 실패했다**
(X-07 (1)(2)(3) · X-08 (4) · X-16 (5) · X-18 (6)). 최고 성적이 LOO R² 0.244 이고, 가용한 최선의
예측변수(매개중심성)가 설명하는 분산이 **약 10%** 다.

**천장이 특정됐으므로 더 시도하지 않는다.** 실질 교차로 1,923개를 R² 0.08 로 채우면 추정치의
92% 가 잡음이다. 그것을 지수에 넣으면 교통량이 없는 것보다 나쁘다 — 잡음을 더하면서
커버리지가 확보됐다는 착각까지 만든다.

**기각 사유는 방법이 아니라 자료의 성질이다** (X-17). 교통량은 공간적으로 매끄러운 장이
아니라서 거리 가정에 기대는 계열(IDW·크리깅·거리회귀·망거리) 전체가 원리상 작동하지 않는다.
속성 기반 대체도 안 된다 — 차수·차로수·등급·제한속도를 전부 결합해 R² 0.116.

**따라서 이 자료는 68개 노드에서만 값을 갖는다.** 그 68개를 어떻게 쓸지는 §0.2-A 에서 미정이다.

## D-16. 차량 차폐는 동적 지수가 아니다 — 평일 주간의 정적 노출 속성이다

`GIS/historical_panoids_filtered.csv` 의 촬영 메타데이터로 확인했다 (X-19).

"서로 다른 해의 임의의 순간"이라는 우려는 틀렸다. **2024년 9월 평일 낮에 집중된 한 번의

**구조적으로 담을 수 없는 것**: 출퇴근 첨두 · 야간 · 주말 · 겨울, 그리고 **단오제 같은 특정

**미결**: 촬영조건이 순위 분산의 17.2% 를 설명하므로 보정이 필요하나, 2026 촬영분은 구조물
차폐도 함께 높아 연도를 통제하면 진짜 공간 차이까지 지울 위험이 있다 (X-19). 보정 여부는
§0.2-A 에서 미정이다.

## D-17. 링크 동적 지수를 PoC 근사로 도입한다 — D-15 를 예측 목적으로 한정한다

**D-15 를 뒤집는 것이 아니다.** 교통량의 공간 확장이 예측으로서 실패했다는 결론(천장 10%)은
그대로다. 바뀐 것은 **목적**이다 — 정확한 링크 통행량을 얻으려는 것이 아니라, DSI 에 동적 항을
결합하는 **구조가 작동함을 링크 단위로 보이는 것**이 목적이다. 그래서 산출물에 신뢰도 플래그를
의무화하고 성능을 낮은 그대로 공시한다.

**절차** (§1.2 수식, `composite/link_dynamic.py`)

| 단계 | 내용 |
|---|---|
| 1 단위 보정 | 교차로 진입량 / 차수. 진입량 중앙 19,784 -> 링크 몫 6,022 |
| 2 IDW 보간 | k=5, p=1, 링크 중점 기준 (X-23 에서 재선택) |
| 3 정규화 | 상하위 1% 클리핑 후 min-max |
| 4 결합 | `DSI_t = α·DSI_static + (1-α)·(β·V_norm + (1-β)·P_resid)` |
| — | `P_resid` 는 주정차 대리의 **통행량 잔차** (D-13). 원지표를 쓰면 이중계산 (A-08) |

`β=0.720`, `α=0.226` 은 D-14 의 순위척도 계수비 `1 : 2.47 : 0.96` 에서 유도했다. 임의값이 아니다.
→ **두 값 모두 교체됐다.** `β` 는 원시 사고자료로 재유도해 **0.398** (D-20), `α` 는 유도 불가로
판정되어 **시나리오 0.20/0.35/0.50** 이 됐다 (D-21). 이 문단은 당시 기록으로만 읽는다.

**신뢰도 플래그가 이 지수의 성립 조건이다.**

| `data_source` | 링크 | 연장 | 처리 |
|---|---:|---:|---|
| `실측` | 228 (4.9%) | 20.4km | 계측 교차로에 접속한 링크 |
| `보간` | 4,306 (91.7%) | 370.3km | IDW 근사 |
| `정적DSI만` | 39 (0.8%) | 7.8km | 계측점 1km 초과 -> `DSI_t = DSI_static` |
| `정적DSI없음` | 124 (2.6%) | 13.7km | DSI 지점 없음 -> 동적 항 미적용 |

**91.7% 가 보간값이다.** 플래그 없이 배포하면 근사를 실측으로 오인하게 만든다 (§4.3).

**성능은 낮다.** 보정값 기준 LOO R² **+0.123**, 배수오차 중앙 1.42 · p90 2.52. 이 수치를
예측 성능으로 인용하면 안 되고, "근사의 오차 크기"로만 적는다.

**교체 가능하도록 설계했다.** 실측이 확충되면 해당 링크의 `v_link` 만 실측치로 바꾸고
`data_source` 를 `실측` 으로 올리면 된다. 구조는 그대로다.

**한계**: 1단계의 차수 균등분배는 방향별 분할비를 무시한다. 그리고 X-23 이 보였듯 차수 보정
자체가 예측력을 깎는다 — 단위 일관성을 위해 감수한 선택이다.

## D-19. 결합 가중치는 잠정값이다 — 결과변수가 절단 자료이기 때문

D-14 의 유도 **방법**(순위 척도)은 유효하다. 문제는 **입력 자료**다 (X-24).

가중치는 "엣지가 사고위험지역과 겹치는가"를 결과로 삼아 뽑았는데, 그 자료는 **사고 4건 이상만
수록된 선정 결과**다. 셋이 걸린다.

1. **통제군 오염** — 사고 1~3건 도로가 0건과 똑같이 비사례로 들어간다. 계수가 0 쪽으로 눌린다.
2. **결과변수에 노출도가 내재** — `사고건수 = 통행량 × 위험도` 이므로 통행량이 많으면 위험도가
   같아도 임계를 먼저 넘는다. **"통행량이 가장 중요하다"의 일부는 선정 규칙을 되찾은 것**일 수 있다.
3. **다발지역은 행정 쿼터** — 연 3건 고정. (가중치 유도에는 안 썼고 X-03 심각도에만 썼다.)

**따라서 이렇게 읽는다.**

| 값 | 지위 |
|---|---|
| `w_s : w_t : w_v = 1 : 2.47 : 0.96` | **잠정.** 확정 가중치로 제시하지 않는다 |
| `α = 0.226` | **정적 비중의 하한.** 실제는 더 클 수 있다 |
| `β = 0.720` | 통행량 과대 가능성이 그대로 반영돼 있다 |
| `w_v` | 이미 0.40~0.96 비수렴 (X-15) |

**영향받지 않는 것**: DSI 자체는 사고 자료를 전혀 쓰지 않는다. 순위 척도 유도(D-14)의 방법론적
개선도 유효하다. 오염된 것은 **결합 가중치 셋뿐**이다.

**해소 경로**: 사고 원시 자료(지점 좌표) 수급. 임계 아래 사고까지 들어오면 통제군 오염과 노출도
내재가 함께 풀린다. 절차는 §5.5.

## D-20. `β = 0.398` — 원시 사고지점으로 재유도

D-19 가 예고한 재유도를 원시 자료로 수행했다 (X-25). **`β` 만 확정된다.**

포아송 회귀 (엣지 n=3,706, 사고 185건, log(길이) offset, 계측점 75군집 강건 SE):

| 항 | 계수 | SE | z | 95% CI (군집 부트스트랩) |
|---|---:|---:|---:|---|
| `R_aadt` 통행량 | **+0.929** | 0.619 | 2.40 | [+0.14, +1.71] |
| `R_res` 초과차폐 | **+1.409** | 0.388 | 4.69 | [+0.84, +2.05] |
| 도로폭 (통제) | +0.047 | 0.009 | 5.07 | — |

```
β = 0.929 / (0.929 + 1.409) = 0.398        절단 자료의 0.720 을 대체
```

**순서가 뒤집혔다.** 절단 자료에서는 통행량 2.47 : 주정차 0.96 으로 통행량이 2.6배였는데,
원시 자료에서는 **주정차 대리가 통행량보다 1.5배 크다.**

**X-24 의 예측이 맞았다.** 4건 임계가 통행량 가중치를 부풀리고 있었다. 부트스트랩 1,000회에서
새 β 가 0.720 이상일 확률은 **0.1%**, `R_res > R_aadt` 일 확률은 82.8% 다.

설정을 바꿔도 안정적이다 — 폭 미통제 0.422 · 스냅 15m 0.418 · 스냅 50m 0.413 · 차폐 원지표 0.315.

**한계**: 자료가 **중상 이상만**이다. 건수 절단은 풀렸으나 심각도 절단이 새로 들어왔다.
경상 사고는 좌표가 제공되지 않는다 (§5.5).

## D-21. `α` 는 자료로 유도하지 않는다 — 설계 파라미터로 둔다

같은 모형에서 **DSI 계수가 음수**로 나왔다 (−0.959, 95% CI [−2.29, +0.20]). 비율
`w_s : (w_t + w_v)` 가 성립하지 않는다. 기계적으로 계산하면 `α = −0.695` 가 나오는데,
이것은 **DSI 를 빼라**는 뜻이라 지수의 목적과 정면으로 충돌한다.

**왜 음수인가** — 이 기록 안의 다른 결과들과 일관된다.

| 근거 | 내용 |
|---|---|
| X-13 | DSI 는 **교차로 근처가 오히려 낮다** (75m 까지 유의) |
| D-05 · X-10 | 도로폭이 억제변수 — 넓은 길일수록 사고 |
| X-25 | 중상 사고 216건 중 **59% 가 교차로**. 도로폭 계수 z=5.07 |

**중상 이상 사고는 넓은 간선 교차로에서 나고, DSI 는 그런 곳을 안전하게 평가한다.**

**해석 — 검증되지 않았다.** DSI 는 자율주행 셔틀의 **시야 차폐**를 재는 지표이고, 사람 운전자가
간선 교차로에서 내는 중상 사고와는 실패 모드가 다르다. 그렇다면 `α` 는 "구조적 시야 위험을
일반 교통 노출 대비 얼마로 칠 것인가"라는 **적용 맥락의 선택**이지 사고 자료가 답할 질문이
아니다. 다만 이 해석 자체가 확인되지 않았다 — 경상 사고 좌표가 있으면 검증할 수 있다.

**따라서 시나리오로 병기한다.**

```
α ∈ {0.20, 0.35, 0.50}      대표값 0.35 (웹 버전 260820_2)
```

**구간의 폭이 작지 않다.** 링크 단위에서 α=0.20 과 0.50 사이 순위상관 +0.863, **상위 10% 의
52% 가 교체**된다. 이것을 감추지 않고 함께 제시한다 — `link_dynamic_index.csv` 에
`dsi_t_a020` · `dsi_t_a035` · `dsi_t_a050` 세 열을 모두 낸다.

**D-19 는 이로써 절반만 해소됐다.** `β` 는 확정, `α` 는 추정 대상에서 제외.

## D-22. 웹 사고 오버레이를 선정 구역에서 원시 지점으로 교체한다

**교체 이유는 표시 방식이 아니라 자료의 성질이다.** 종전 오버레이(링크기반 위험지역 64건 ·
지자체 다발지역 24건)는 사고 4건 · 9건 이상만 수록된 **선정 결과**다 (X-24). 그래서 지도에서
비어 보이는 곳이 "사고가 없는 곳"이 아니라 **"임계 미달"** 이었다. 지도를 보는 사람이 그
구분을 할 방법이 없었다.

| | 이전 | 이후 |
|---|---|---|
| 자료 | 위험지역 64 + 다발지역 24 (선정 구역) | **원시 지점 216건** |
| 기간 | 2017~2025 | 2024~2025 |
| 레이어 | 위험지역 / 다발지역 | **사망 20 / 중상 196** |
| 기하 | 폴리곤 (면 · 테두리 원) | 원형 마커 |
| 임계 | 4건 / 9건 이상 | **없음 (전수)** |

**두 겹의 마커 크기는 같게 둔다** (반지름 6.5px). 색으로만 구분한다 — 중상 196건이 사망 20건과
같은 비중으로 보여야 분포가 읽힌다. 크기를 달리하면 건수가 많은 쪽이 시각적으로 눌린다.
범례 스와치도 같은 규칙으로 맞췄다.

**연도 토글은 구조를 그대로 쓴다.** `AccidentLayer` 타입 하나로 매개변수화돼 있어 키만
`riskArea|hotspot` → `fatal|serious` 로 바꾸면 전체선택·해제까지 그대로 동작한다.
연도는 2024/2025 두 해로 줄었다.

**옛 geojson 두 개는 지우지 않는다.** 웹에서는 더 이상 읽지 않지만 `accident/frequency.py` ·
`frequency_idw.py` · `severity.py` 가 입력으로 쓴다. 지우면 D-05 · D-14 · X-03 의 재현이 깨진다.
지우려면 심각도 분석(X-03)을 먼저 원시 자료 기반으로 옮겨야 한다 — 빈도 쪽은
`weight_rederive_raw.py` 로 이미 옮겼다.

**남는 한계**: 중상 이상만이다. 경상·부상신고는 TAAS 가 좌표를 주지 않는다 (§5.5).
**오버레이의 빈 곳을 "사고 없음"으로 읽으면 안 된다** — 임계 문제는 사라졌지만 심각도
절단은 남아 있다 (§4.3).

`web/scripts/build_accident_points.py` 로 만든다. 재생성 절차는 §5.7.

## D-23. 웹에서 `α` 를 조절할 수 있게 한다

D-21 이 `α` 를 **설계 파라미터**로 판정했으므로, 값을 하나로 박아 보여주면 그 성격이 감춰진다.
슬라이더로 직접 움직이게 두어 **결과가 `α` 에 얼마나 의존하는지를 보는 사람이 확인**하도록 한다.

**방식 — 성분을 실어 브라우저가 합성한다.**

```
자료:  {..., "s": 정적성분, "d": 동적성분}      지점 · 도로 · 노선 모두
표시:  dsi = α·s + (1-α)·d                    versions.ts 의 combineAlpha
임계:  그 α 의 분포에서 3분위를 다시 뽑는다     versions.ts 의 tercilesOf
```

**임계를 다시 뽑는 것이 핵심이다.** 고정 임계를 쓰면 `α` 를 올릴 때 값 전체가 내려가며 등급이
한쪽으로 쏠린다. 분포에서 다시 뽑으면 항상 3등분이 유지되어, 슬라이더가 **순위 구조의 변화**만
보여준다. 대신 서로 다른 `α` 의 등급끼리는 비교할 수 없다 (§4.3).

`dsi`·`grade` 필드는 기본 `α` 로 미리 채워 둔다 — 성분을 모르는 소비자도 그대로 쓸 수 있다.
정적전용 지점(계측점 1km 초과)은 `d` 를 `s` 와 같게 둬서 `α` 와 무관하게 정적값이 나온다.

**자료 생성 — 공용 집계기를 재사용한다.** 도로·노선 성분을 얻으려고 집계 규칙(특히 노선 버퍼
20m)을 복제하지 않는다. `s`/`d` 를 각각 `dsi` 로 담은 임시 지점맵을 만들어 `build_road_dsi_map.py`
와 `build_bus_route_dsi.py` 에 그대로 태운 뒤 결과를 병합한다 (`build_alpha_parts.py`).
공용 스크립트는 손대지 않는다.

**적용 범위**: `versions.ts` 의 `alphaAdjustable` 이 켜진 판만 슬라이더가 나온다. 성분이 없는
옛 버전은 파일의 `dsi` 와 고정 임계를 그대로 쓴다 — 한 컴포넌트가 두 방식을 모두 다룬다.

**슬라이더가 드러내는 것** — 노선 평균이 `α` 에 따라 순서까지 바뀐다.

| `α` | A | C | B |
|---:|---:|---:|---:|
| 0.20 | 0.466 | 0.340 | 0.325 |
| 0.35 (기본) | 0.397 | 0.288 | 0.282 |
| 0.50 | 0.327 | 0.235 | 0.239 |
| 1.00 (정적만) | 0.096 | 0.061 | **0.095** |

`α` 가 커질수록 A 와 B 의 격차가 사라진다. **"A 가 가장 위험하다"는 결론이 `α` 선택에 크게
의존한다**는 뜻이고, 이것이 슬라이더를 둔 이유다.

## D-24. 목적을 이벤트 기간으로 한정하고, 판 간 비교가 되도록 척도를 공유한다

프로젝트 목적을 **특수 이벤트 기간의 자율주행 셔틀 노선 설계**로 좁혔다. 시나리오는
**강릉단오제**(2025-05-27~06-03 · 2026-06-15~06-22)다. 그러면 동적 항의 통행량도 그 기간
값이어야 한다.

### 무엇을 바꾸고 무엇을 그대로 두는가

| 대상 | 이벤트 기준으로 | 이유 |
|---|:--:|---|
| 통행량 입력 `V_norm` | **바꾼다** | 목적이 이벤트 기간 노선 설계다 |
| `β` (통행량:차폐) | **유지** | 아래 참조 |
| `α` (정적:동적) | 유지 | 애초에 자료로 정하지 않는 설계값 (D-21) |
| `DSI_static` | 유지 | 시간 불변 지표 |
| 차폐 항 | **불가** | 파노라마가 2024-09 평일 낮이다 (D-16) |

**`β` 를 이벤트로 재유도할 수 없다.** β 는 "통행량 한 단위당 사고" 대 "차폐 한 단위당 사고"의
비율이므로 **이벤트 기간의 사고**가 필요한데, 축제 창이 두 해 합쳐 16일이고 사고 원시자료는
**월 단위까지만 제공**된다(`발생년월`). 날짜로 자를 수조차 없고, 잘라도 한 자릿수다.

β 가 재는 것은 "통행량이라는 변수와 사고의 관계"이지 "이번 주 통행량이 얼마인가"가 아니다.
그 관계는 연중 자료로 추정하는 편이 오히려 정확하다.

**차폐 항은 이벤트로 바꿀 수 없다.** 축제 때 가장 크게 달라질 법한 것이 주정차인데, 파노라마는
평일 낮 스냅숏이다. **동적 항의 절반이 평시**로 남는다 — 한계로 명시하고 진행한다.

### 기준선은 연평균이 아니라 축제 창 앞뒤 28일

같은 계절·요일 구성과 비교해야 계절 효과가 통제된다. 연평균 대비로 재면 여름 성수기 상승분이
축제 효과에 섞인다. 실제로 두 기준선의 배율 순위상관이 0.73~0.77 로 완전히 같지 않다 (X-27).

### 두 해를 나눈다

`danoje_2025` · `danoje_2026` 두 판이다. 한 해만 보면 그해 특수 상황인지 구분할 수 없다.
두 판을 견주면 배율 순위상관 **rho +0.725**, 상위 10 중 7개 겹침으로 축제 효과가 재현된다.

### 척도를 판 간 공유한다 — 이것이 없으면 이벤트판이 무의미하다

처음 만들었을 때 이벤트판이 평시판과 **도로 순위상관 0.9992**, 등급이 바뀐 도로 102/4,515 에
그쳤다 (X-27). 원인은 자기정규화다 — 축제는 통행량의 **수준**을 바꾸지만(중앙 1.11배)
**순위**는 거의 그대로인데(rho 0.98), 지수가 판마다 min-max 로 다시 펴면서 수준 변화를
되돌린다.

**해법 둘.**

```
정규화 기준점   기준판(평시)의 min/max 를 모든 판이 공유    data/norm_anchors.json
등급 임계       α별 격자를 기준판 분포에서만 뽑는다        terciles_grid.json (α 0~1, 21점)
```

임계를 **완전히 고정하지 않고 α별로 둔** 이유: 고정하면 α 를 움직일 때 값 분포가 통째로
이동해 등급이 한쪽으로 쏠린다(D-23 이 피하려 한 문제). α별로 두되 **항상 기준판에서** 뽑으면
같은 α 에서 모든 판이 같은 잣대를 쓰므로 비교가 되고, 슬라이더도 의미를 유지한다.

**함정 하나**: 기준점을 공유하면서 클리핑까지 기준판 상한으로 하면 축제의 초과분이 잘린다.
기준판만 클리핑하고 다른 판은 **선형 변환만** 적용한다. 그래서 이벤트판의 `V_norm` 은
1 을 넘고(−0.19~1.60), `DSI_t` 최대가 1.21 이다.

### 결과

| 판 | High-risk 도로 | 노선 A |
|---|---:|---:|
| 평시 `260820_2` | 33.3% | 0.3967 |
| `danoje_2025` | **39.3%** | 0.4103 |
| `danoje_2026` | **38.1%** | 0.4115 |

축제 기간에 고위험 도로가 **33% → 38~39%** 로 늘어난다. 가장 크게 오르는 교차로는 두 해 모두
`노암하나로마트4거리`(1.18~1.26) · `객사문사거리` · `노암한라4차삼거리` · `임당성당교차로` 로,
**단오장(남대천 둔치) 남쪽과 구도심 축**이다.

**D-23 의 임계 서술이 이로써 바뀐다** — "그 α 의 분포에서 다시 뽑는다"가 아니라
**"그 α 의 기준판 분포에서 뽑는다"** 다. 웹은 `terciles_grid.json` 을 받아 쓰고, 못 받으면
기존 방식으로 폴백한다.

# §3. 실험 기록

## X-01. API `resultCode=10` 의 정체

문서에 없는 동작. **입력 세그먼트 중 하나라도 내부 세부링크에 매칭되지 않으면 요청 전체가
`10`** 이 된다. `03`(NODATA)이 아니라 파라미터 오류로 떨어진다.

실측 (강릉대로, 50m 간격 단독 조회):

```
seg[0]   0~ 50m  code=00 val=5.53  grd=2
seg[1]  50~100m  code=00 val=0.00  grd=1
seg[2] 100~150m  code=10   ← 이 구간이 섞이면 그 요청 전체가 실패
seg[3] 150~200m  code=00 val=0.22  grd=1
```

이 때문에 처음엔 "정점 6개 제한"으로 오독했다. 정점 수 제한이 아니고 실패 세그먼트의 포함
여부다 — 2점 500m 요청도 정상 동작한다.

→ 다중 세그먼트 요청은 실패 시 **이분 분할**해서 매칭 가능한 세그먼트만 건져야 한다.

## X-02. 차단·네트워크 실패가 결측으로 위장됐다

초기 `koroad_client.py` 는 `code != "00"` 을 전부 "세부링크 미매칭"으로 처리했다. 그 결과
**인증키 차단(`30`)과 네트워크 실패가 결측으로 위장되어 매칭률 통계가 오염**됐다.

간격 민감도 테스트에서 노선 A 가 대부분 0% 로 나온 것이 이 오염의 결과다. 허용량 소진 직후
에는 API 경로가 `connect timeout` 으로 응답조차 하지 않다가, 이후 `resultCode=30
SERVICE_KEY_IS_NOT_REGISTERED_ERROR` 로 바뀐다.

→ 현재 클라이언트는 `30`/네트워크 실패를 `QuotaError` 로 **즉시 중단**하고, `Client(budget=N)`
으로 실행당 호출 상한을 두며, `cli.codes` 에 resultCode 분포를 기록한다. 러너의 `save()` 는
빈 결과가 기존 파일을 덮어쓰지 못하게 막는다 (부록 A-01).

**허용량은 날짜가 바뀌면 초기화된다.** 별도 활용신청은 필요 없었다.

## X-03. 심각도 상관 — 귀무

| 검정 | 링크기반 (n=61) | 지자체별 (n=24) |
|---|---|---|
| 구역 평균 DSI | rho +0.126 (p=0.33) | rho −0.001 (p=1.00) |
| 구역 상위10% DSI | +0.198 (p=0.13) | +0.208 (p=0.33) |
| 등급·폭 통제 편상관 | +0.185 (p=0.15) | +0.393 (p=0.057) |
| 상·하위 절반 합산 (Fisher) | OR 1.153 (p=0.49) | OR 0.834 (p=0.51) |

링크기반은 전부 약한 양의 방향으로 일관되지만(0.13~0.20) 유의수준 근처도 아니다.

**지자체별의 p=0.057 은 믿을 게 못 된다.** 같은 데이터에서 통제 전 rho 가 −0.001 인데 통제 후
+0.393 으로 튀고, 합산 오즈비는 반대 방향(0.834)이다. n=24 에 공변량 둘을 넣은 결과이고,
검정을 10회 돌렸으니 전부 귀무여도 p<0.05 가 한 번 나올 확률이 40% 다.

**부수 발견**: 구역 상위10% DSI 가 두 데이터셋 모두에서 일관되게 가장 높은 rho 를 냈다.
"구역 평균이 아니라 최악 지점이 사고를 만든다"는 이론과 맞는다 → 주 검정 후보 (§0.2-B).

## X-04. 검정력 — 애초에 잡을 수 없는 크기였다

```
n=61  → |rho| ≥ 0.352 여야 80% 검정력
n=24  → |rho| ≥ 0.545
```

목표 상관별 필요 n: rho 0.15 → **347** / 0.20 → **194** / 0.25 → 124 / 0.30 → 85.
관측값 0.13~0.20 은 정확히 사각지대에 들어간다.

**세 가지가 겹쳤다.**

- **유사복제**: 64개 구역이 실제로는 서로 다른 장소 **36개**다(100m 기준). 같은 자리가 최대
  6개년 중복. 유효 n 은 36 에 가깝고, 보고된 p값은 그만큼 낙관적이다.
- **범위제한**: 전체 지점 DSI 는 SD 0.222(1.15~2.27)인데 구역 평균은 SD 0.099(1.17~1.53)로
  **44%** 로 깎였다. 평균을 내면서 한 번, 대상이 전부 도심권이라 또 한 번 줄었다.
- **분모 잡음**: 구역당 사고 중앙 9건. 심각도 비율의 이항 표준오차가 0.138 이다.

**기각한 대응** — 장소 단위 통합: n 61→36 으로 줄어드는데 분모 중앙값은 9 그대로다(반복
장소가 소수라 평균만 17 로 오름). 순손실. 사고 10건 이상 필터: n 61→28, rho 0.126→0.031.
잡음보다 신호를 더 많이 버린다.

## X-12. AUC — 결합은 DSI 단독보다 낫지만 통행량 단독보다 낫지는 않다

교차로 150m 이내 사고지점 여부를 맞히는 AUC (부트스트랩 95% CI).

| 지수 | 지자체별 다발지역 (사례 8/75) | 링크기반 위험지역 (사례 28/75) |
|---|---|---|
| 정적 DSI 단독 | 0.459 [0.259, 0.673] | 0.601 [0.464, 0.735] |
| 정적 DSI 상위10% | 0.513 | 0.597 |
| **통행량 단독** | **0.756** [0.565, 0.911] | 0.663 [0.525, 0.793] |
| 차량차폐 단독 | 0.664 | 0.625 |
| CDI (DSI+통행량) | 0.688 [0.468, 0.866] | 0.669 [0.540, 0.785] |
| CDI (+차량차폐 w=1) | 0.705 | **0.679** [0.551, 0.802] |

**결합이 DSI 단독보다는 확실히 낫다**(0.459→0.688, 0.601→0.669). 그러나 **다발지역에서는
통행량 단독(0.756)이 결합(0.688)보다 높다** — DSI 를 섞으면 오히려 떨어진다.

신뢰구간이 전부 크게 겹쳐 어느 쪽이 낫다고 단정할 수 없다. **가중치를 링크기반에서 뽑아
링크기반으로 검증한 열(0.669)은 순환이라 독립 검증이 아니다.**

**해석**: 사고지점 예측만이 목적이라면 통행량만 쓰는 게 나을 수 있다. 결합의 근거는 예측력이
아니라 **목적이 다르다**는 데 있다 — 사고 이력이 없는 구간도 사전 진단하는 것이 DSI 의
취지이고 통행량은 그걸 못 한다. 이 표는 "결합이 예측을 개선한다"가 아니라 **"결합해도
예측력이 유지되면서 사전 진단 능력이 더해진다"** 로 써야 한다.

**부수 결과**: 결합은 순위를 실제로 바꾼다. 정적 DSI 단독 순위와의 상관 0.612, **75개 중
50개가 10위 이상 이동**. 예: `교동사거리` DSI 23위 → 통행량 8위 → 종합 8위.
`강릉교사거리` DSI 38위 → 통행량 5위 → 종합 9위.

## X-13. 반경 선택 — 신뢰도 기준은 실패했고 감쇠 프로파일이 답을 줬다

### 기각된 기준 — 집계 신뢰도의 최댓값

"반경이 작으면 표본이 적어 잡음, 크면 진입로·다음 블록까지 평균해 교차로 간 분산이
무너지므로 유한한 r 에서 최대가 된다"는 설계였다. ICC 계열로 정의했다.

```
reliability = (var_between - mean(var_within / n)) / var_between
```

**30m→300m 에서 0.826 → 0.986 으로 단조증가했다. 최댓값이 없다.**

원인은 `var_between` 이 어느 반경에서도 0.09 로 평평하다는 것이다. 300m 까지 평균해도 DSI 장의
공간구조가 씻기지 않는다. 그러면 남는 것은 `1/n` 뿐이라 반경이 클수록 좋아지는 양이 된다.
**애초에 최댓값을 갖도록 설계된 통계량이 아니었다.** `composite/radius_sweep.py` 에 기록으로 남긴다.

### 채택된 기준 — 방사 감쇠 프로파일

각 DSI 지점을 **최근접 교차로에만** 배정해(중복계산 없음) 거리대별 평균을 냈다. 배경은
400~600m 대(n=6,420), CI 는 교차로 단위 군집 부트스트랩 400회. `composite/radius_profile.py`.

**발견 ① — DSI 는 교차로 근처가 오히려 낮다.**

0~25m 에서 1.2485, 배경 1.3458 → **−0.0973 (정적 DSI 1SD 의 0.47배, 부호는 음)**. 거리와 함께
단조 상승해 100m 에서 배경과 만난다. 225~350m 에서는 되레 유의하게 높다(+0.036~+0.047) —

## X-15. `w_v` 유도 — 두 경로가 수렴하지 않았다

불법주정차 실측이 없으니 검증은 불가능하다. 대신 **서로 독립인 두 경로**로 유도해 비교했다.

### 경로 ① 빈도모형 계수비 (D-07 을 순위 척도로 확장)

모형에 `log(교통량)` 이 들어 있으므로 차폐 계수는 **통행량을 통제한 부분효과**다 —
D-13 이 요구하는 조건과 일치한다. FWL 정리대로 원지표를 넣든 잔차를 넣든 차폐 계수는
거의 같다 (+0.9338 vs +0.9209).

| 모형 | `w_s : w_t : w_v` |
|---|---|
| A 차폐 없음 | 1 : 3.75 : — |
| B 차폐 원지표 | 1 : 2.29 : 0.98 |
| **C 초과차폐 (채택)** | **1 : 2.47 : 0.96** |

### 경로 ② 파이프라인 내부 탄력도

파이프라인은 이미 `dsi_veh`(차량 차폐를 포함한 DSI)를 계산한다. 즉 차폐를 구조적 위험
대비 얼마로 칠지에 대한 **내부 답**을 갖고 있다. 순위 척도로 읽으면 (n=34,724):

```
rank(dsi_veh) = -0.133 + 0.904·rank(DSI) + 0.363·rank(차폐)
```

**`w_v / w_s = 0.40`**.

### 수렴하지 않는다 — 그래서 구간으로 제시한다

**0.96 (빈도모형) vs 0.40 (파이프라인 내부).** 2.4배 차이다. 둘은 다른 질문에 답하므로
어느 쪽이 옳다고 할 근거가 없다 — ①은 "사고 이력과의 연관", ②는 "파이프라인이 스스로
매기는 비중"이다. **`w_v = 0.40 ~ 0.96` 구간으로 제시한다.** §0.2 의 "단일값이냐 구간이냐"
는 이로써 결정이 아니라 **결과**가 됐다.

### 다행히 실질 영향은 작다

`w_s : w_t = 1 : 2.47` 고정, `w_v` 를 구간 안에서 움직였을 때 (기준 0.40):

| `w_v` | 순위상관 | 10위 이상 이동 |
|---:|---:|---:|
| 0.70 | +0.9950 | 0/75 |
| 0.96 | +0.9834 | 1/75 |

**구간의 폭이 순위를 거의 바꾸지 않는다.** 수렴 실패가 결론을 흔들지는 않는다.
출력에는 `cdi_0.0`(시나리오 없음) · `cdi_0.4` · `cdi_0.7` · `cdi_0.96` 을 병기한다.

## X-18. 보간 실패 (6) — 노드 단위 추정, 중심성은 유의하지만 예측하지 못한다

## X-23. 차수 보정의 효과 — 단위는 맞지만 예측력을 깎는다

D-17 의 1단계(진입량/차수)가 성능에 어떤 영향을 주는지 분리 측정했다. 같은 IDW 설정에서
대상만 바꿔 LOO 를 돌렸다 (계측점 75개, log 척도).

| IDW 설정 | 보정 전 (진입량) | 보정 후 (진입량/차수) |
|---|---:|---:|
| k=3, p=2 | +0.232 | **+0.013** |
| k=3, p=1 | +0.247 | +0.068 |
| **k=5, p=1** | +0.256 | **+0.123** |
| k=5, p=2 | +0.247 | +0.059 |

**보정이 R² 를 0.232 -> 0.013 으로 깎는다** (k=3,p=2 기준). 원인은 명확하다.

```
차수 ~ 진입량   rho +0.032
차수 분포       4지 45 · 3지 18 · 2지 11 · 1지 1  (계측점 75개)
```

**차수는 진입량에 대한 정보를 사실상 갖고 있지 않다.** 나누면 신호는 안 빠지고 잡음만 들어간다.
게다가 나누는 값의 폭이 좁아(대부분 3 또는 4) 보정의 실익도 작다.

**보정 전 수치(0.232~0.256)가 X-07 의 0.244 를 재현한다.** 즉 **0.244 는 보정 전 값이며,
D-17 파이프라인의 성능이 아니다.** 문서화에 이 수치를 쓰면 대상이 다른 값을 인용하게 된다.

**설정 재선택**: 처음 지시된 k=3, p=2 는 보정 후 R² 0.013 으로 사실상 전역 평균이다.
k·p 는 이론적 근거가 있던 값이 아니므로 **k=5, p=1 (R² 0.123)** 로 바꿨다. 개념적 비용 없이
9배 개선된다.

**차수 보정을 유지하는 이유**는 예측력이 아니라 **단위 일관성**이다 — 관측값이 교차로 진입량인
채로 링크에 붙으면 값의 의미가 링크 통행량이 아니게 된다. D-17 은 정확도가 아니라 구조 시연이
목적이므로 이 교환을 받아들였다. 기록해 두지 않으면 "왜 성능이 더 나쁜 설정을 쓰나"가 반복된다.

## X-24. 결과변수가 원시 사고가 아니라 선정된 구역이다

가중치 유도(D-14)의 결과변수가 어떤 자료인지 뜯어봤다.

| | 링크기반 위험지역 | 지자체 다발지역 |
|---|---:|---:|
| 건수 | 64 | 24 |
| **`acc` 최소값** | **4** | **9** |
| 중앙 / 최대 | 8 / 35 | 13.5 / 21 |
| 추가 제약 | — | **연 3건 행정 쿼터** |

**`acc` 최소값이 4 와 9 에서 정확히 끊긴다.** 사고 3건인 도로는 자료에 존재하지 않는다.

**임계 바로 위 쌓임**: 사고건수 분포가 `4건 12개 · 5건 5개 · 6건 7개 …` 로 4 에서 최빈이다.
절단의 전형적 형태다. 3건과 4건 사이에 실질적 차이가 없는데 결과변수는 0/1 로 갈린다.

### 세 가지 문제

1. **통제군 오염.** "겹치지 않는 엣지"에 사고 1~3건 도로가 섞여 있다. 계수가 0 쪽으로 눌린다
   (감쇠). 실제 효과는 추정치보다 클 가능성이 높다.
2. **노출도 내재.** 맞히려는 것은 "사고가 났나"가 아니라 **"4건 임계를 넘었나"** 다.
   `사고건수 = 통행량 × 위험도` 이므로 임계 통과 자체가 통행량 편이다.
3. **행정 쿼터** (다발지역). 실제 집중도가 아니라 그해 상위 3곳이다.

### 확인해봤으나 결론을 못 낸 것

지정된 64건 **안에서** 사고건수가 통행량을 따라가는지 봤다 (계측점 500m 내 54건).

```
사고건수 ~ 인근 통행량   rho +0.178   p 0.197      (유의하지 않음)
사고건수 ~ 경상자수      rho +0.772                (내적 일관성 확인)
```

약하게 나왔지만 **이미 4건을 넘긴 것들끼리의 비교**라 범위 제한이 걸려 있다. **"문제 없음"의
근거로 쓸 수 없다.** 정작 문제인 통제군(0~3건)은 자료에 없어서 측정 자체가 불가능하다.

### 편향의 방향

1 은 세 변수에 비슷하게 걸리므로 **비율은 살아남을 수 있다** — 지수는 비율만 쓴다.
문제는 2 다. **통행량에만 선택적으로 걸린다.** 방향은 **통행량 과대 · 정적 과소**이고,
따라서 `α = 0.226` 은 하한이다 (D-19).

민감도로 보면 `α` 를 0.226 → 0.5 로 올릴 때 지점 순위상관이 **0.88** 까지 떨어진다.
동적 항을 통째로 빼도(α=0) 0.93 이다. **`α` 가 `β` 보다 결과를 크게 좌우한다.**

## X-26. 사고 하위유형별 — DSI 의 음수는 차대차에 국한된다

현재 DSI 는 **어떤 결과변수에서도 양의 연관이 확인되지 않았다.**

**차폐가 잘 맞히는 곳이 정확히 차폐가 기전일 법한 곳**이라는 점에서 내적으로 일관된다.

자율주행 셔틀이 가장 취약한 실패 모드는 **가려진 곳에서 나오는 보행자**다. 파이프라인의 핵심
측정(차폐)이 바로 그 사고 유형과 연결된다는 것은, 결합 지수 전체보다 **이 부분이 현재 가장 잘
뒷받침된다**는 뜻이다.

### 한계 — 확증이 아니다

- **탐색적이다.** 8개 부분집합을 돌렸다. 전부 귀무여도 하나쯤 p<0.05 가 나올 확률이 34% 다.
  사전 지정한 검정이 아니므로 방향 탐색으로만 읽는다 (X-03 이 같은 문제로 지적받았다).
- **부분집합이 작다.** 32~115건이다. `R_dsi` 의 SE 가 0.62~0.94 로 커서 대부분의 구간이
  0 을 넉넉히 포함한다.
- **중상 이상만이다.** 경상 보행자 사고가 빠져 있고, 차폐가 기전인 사고는 오히려 경상에 몰려
  있을 수 있다 (§5.5).

**사전 지정 주 검정 후보**: "차폐(초과) → 단일로 보행자 사고" 가 가장 강했다(+2.050). 경상
좌표가 확보되면 이것 하나만 미리 정해 검정하는 것이 X-03 이 못 한 일을 하는 길이다.

## X-27. 축제 효과의 재현성과 자기정규화의 함정

### 기준선 설계 — 연평균이 아니라 인접 28일

축제 창 앞뒤 각 14일을 기준선으로 잡으면 계절·요일 구성이 맞춰진다. 두 해 모두 확보된다.

| | 축제 | 기준선 | 지점 | 배율 중앙 |
|---|---:|---:|---:|---:|
| 2025 (05-27~06-03) | 8일 | 28일 | 75 | 1.020 |
| 2026 (06-15~06-22) | 8일 | 28일 | 75 | 1.020 |

기준선을 무엇으로 잡느냐가 결과를 바꾼다 — 인접 기준 대비 연간 기준의 배율 순위상관이
**0.73~0.77** 이다. 연간 대비로 재면 배율 중앙이 1.02 → 1.05~1.07 로 부풀고, 그 차이는
여름 성수기 상승분이다.

### 자기정규화가 효과를 지웠다 — 처음 만든 판이 무의미했던 이유

이벤트 통행량으로 판을 만들었더니 평시판과 거의 같았다.

| | 값 |
|---|---:|
| 도로 순위상관 (평시 vs 이벤트) | **+0.9992** |
| 등급이 바뀐 도로 | 102 / 4,515 |
| `dsi_t` 값 차이 중앙 | 0.0045 |
| 노선 점수 변화 | A +0.6% · B −0.5% · C −0.1% |

**원인**: 축제는 통행량의 *수준*을 바꾸지만(중앙 1.11배, 배율 0.59~1.22) *순위*는 거의 그대로다
(rho +0.98, 10위 이상 이동 4/75). 그런데 지수는 판마다 min-max 로 다시 정규화하므로
**수준 상승이 그대로 상쇄된다.** 남는 것은 작은 순위 변화뿐이다.

이 상태로는 "이벤트 기간 지수"라는 이름만 붙었을 뿐 실질이 평시판과 같다.

### 척도를 공유한 뒤

| 판 | High-risk 도로 | High-risk 지점 |
|---|---:|---:|
| 평시 `260820_2` | 33.3% | 33.3% |
| `danoje_2025` | **39.3%** | 36.9% |
| `danoje_2026` | **38.1%** | 36.3% |

기준점을 공유하니 이벤트판의 `V_norm` 이 −0.19~1.60 으로 1 을 넘고, `DSI_t` 최대가 1.21 이
된다. 등급이 3등분을 벗어나는 것이 정상이며, **그 이탈 자체가 축제 효과다.**

**중간에 한 번 걸렸다.** 기준점을 공유하면서 클리핑까지 기준판 상한으로 적용했더니 이벤트판의
`V_norm` 이 여전히 0~1 이었다. 초과분이 상한에서 잘려 나갔기 때문이다. 클리핑은 기준판
이상치 억제용이므로 다른 판에는 **선형 변환만** 적용하도록 분리했다 (D-24).

## A-08. 링크 지수에서 주정차 대리를 잔차화하지 않았다
