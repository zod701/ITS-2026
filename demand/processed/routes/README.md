# 강릉 BIS 노선 CSV

## 웹 노선 수요 그라데이션

`build_bis_web_routes.py`는 연간·단오제 노선×정류장 CSV를 각각 ID로 결합한다. 선택 노선에 속한 현재 BIS 정류장의 값만으로 기간별/승하차별 최대값을 구하고 `sqrt(count / maximum)`으로 정규화한다. 노선과 기간마다 범위가 달라 같은 색이 같은 절대 인원을 의미하지 않는다. 범례는 선택한 노선·기간의 실제 최대값을 표시한다.
노선 경로 좌표마다 해당 노선 정류장 중 직선거리 300m 이내의 값을 `(1-distance/300)^2` 가중평균하고, 인접 경로 좌표 사이를 SVG 선 그라데이션으로 연결한다. 승차는 빨강, 하차는 파랑, 혼합은 보라 계열이며 강도는 정규화 수요로 결정한다. 실제 0은 밝은 중립색, 주변 기록 없음은 회색이다. 정류장 점은 수요 색상과 무관한 중립색이다.
이는 정류장 주변 승하차 활동의 시각적 보간이며 재차인원·구간 통행량·OD 추정이 아니다. 가까운 상하행 정류장의 영향은 섞일 수 있다. 현행 경유 목록에 없는 과거 정류장 수요는 선에 배정하지 않는다. 원본 수치는 상세 CSV에 보존된다.

## 2025년 단오제 기간 노선별 승하차

`smartcard data/단오제 raw/0527.csv`~`0603.csv`의 `opr_ymd`가 2025-05-27~2025-06-03임을 확인하고 8일간 합산했다.

- `route_demand_summary_2025_danoje.csv`: 121개 노선의 기간 승하차 합계와 최다 승하차 정류장.
- `route_stop_demand_2025_danoje.csv`: 노선×정류장 4,138행, 승하차 수·노선 내 순위·비중.
- `route_top_stops_2025_danoje.csv`: 승차/하차 각각 상위 5위(동률 포함), 1,190행.
- `demand_validation_2025_danoje.json`: 원본 및 일별 정류장 CSV 대조 결과.

승차 총합 216,314, 하차 총합 107,681. 모든 날짜에서 기존 `station_MMDD.csv`와 ID별 승하차가 일치한다. 110개 노선은 현재 BIS와 연결되고 나머지 11개도 원본 ID·수치를 보존했다. 현재 BIS 중 기간 기록이 없는 노선은 0으로 만들지 않는다.
기간 시작·종료, 제공 일수, 해당 노선/정류장의 기록 존재 일수와 원본의 `rte_nm`을 추가했다. `route_name_source_2025`는 원본 기종점 형태의 명칭이며 현재 BIS 노선번호와 구분한다. 기록 없는 날을 실제 0으로 단정하지 않는다.
순위·분모·미상 정류장 처리는 연간 자료와 동일하다. 재생성: `python TAAS/analysis/prep/build_route_demand.py --danoje`. 연간 파일과 웹 데이터는 변경하지 않는다.

## 2025년 노선별 승하차

- `route_demand_summary_2025.csv`: 원본에 있는 130개 노선별 승하차 총합과 최다 승차·하차 정류장(동률 모두 표시).
- `route_stop_demand_2025.csv`: 노선 ID × 정류장 ID별 5,090행. 승차·하차 수, 노선 내 순위, 노선 총량 대비 비중(%), 현재 BIS 경유 여부.
- `route_top_stops_2025.csv`: 노선별 승차·하차 상위 5위(동률 포함), 1,247행. `metric=ride`는 승차, `goff`는 하차.
- `demand_validation_2025.json`: 원본 합계 보존과 현재 BIS 노선 매칭 검증.

`2025.csv`의 시간대·이용자 유형·정류장 순번을 합산해 `(rte_id, sttn_id)`당 한 행으로 집계했다. 현재 BIS에서 같은 정류장을 반복 경유하더라도 수치를 복제하지 않는다. 현재 경유 순번과 원본 순번은 별도 열로 보존했다.
순위는 양수 수치에만 부여하며 동률은 공동 순위(예: 1, 1, 3)다. 미상 ID `~`는 총량과 상세에는 포함하되 정류장 순위에서는 제외한다. 비중의 분모는 미상 ID를 포함한 해당 노선의 전체 승차 또는 하차 합계다.
현재 BIS와 매칭되는 노선은 116개이며 나머지 14개도 ID와 수치를 보존했다. 현재 BIS에는 있지만 2025 기록이 없는 16개는 0으로 생성하지 않고 검증 JSON에 명시했다. 정류장명이 없을 때는 빈 값이며, 식별 가능한 ID의 순위는 유지한다.
노선명·운수사·좌표·경유 여부는 현재 BIS 기준이다. 2025년에 같은 경로였다는 뜻은 아니다. 승차와 하차는 각각의 집계이며 승객의 출발-도착 연결(OD)을 추정한 자료는 아니다.
재생성: `python TAAS/analysis/prep/build_route_demand.py`.

출처: https://bis.gn.go.kr/search/route 및 `/search/route/map?routeId=…`.
현재 조회 시점의 노선이며 2025년 역사 노선으로 간주하지 않는다.

| 파일 | 단위 / 내용 |
|---|---|
| routes.csv | 노선 ID별 번호, 운수사, 기종점, 정류장 방문 수, 경로 좌표 수, 수집 시각·URL |
| route_stops.csv | 노선별 경유 정류장 방문 순서, 정류장 ID·명칭·좌표 |
| route_geometry.csv | 노선 형상을 구성하는 순서별 좌표, 원본 방향·구간 필드 |
| route_schedules.csv | 노선 운행정보 응답의 첫차·막차·운행 횟수 |
| route_stop_times.csv | 경유 정류장별 원본 시간 응답. avgTime 등 의미를 추가 해석하지 않고 보존 |

UTF-8 BOM CSV. ID는 문자열로 취급한다. 결합 키는 `route_id`이며, 정류장 승하차와의 결합은 `sttn_id`를 사용한다. 같은 노선번호도 운수사·계통별 ID가 다를 수 있다.
반복 방문을 삭제하지 않았다. `response_order`는 원본 배열 순서(1부터), `station_order`·`sequence`는 서비스의 원래 순서 값이다. 경로를 만들 때 `up_down`·`up_down_seq`도 확인하여 방향과 구간이 다른 점을 무조건 연결하지 않는다.
정류장 상세의 first_time/last_time과 노선 운행정보의 값은 서로 다를 수 있어 별도 보존했다. 빈 값은 제공되지 않은 값이며 0으로 대체하지 않았다. 시간 자료만으로 배차간격이나 일자별 실제 운행을 확정하지 않는다.

`raw/`에 원본 JSON과 수집 시각을 보존한다. `validation.json`은 행 수와 빈 노선 목록이다.
재실행: 저장소 루트에서 `python TAAS/analysis/prep/export_bis_routes.py`. 기존 캐시를 재사용하므로 중단 후 이어서 실행 가능하다.
`demand/`는 기존 `.gitignore`에 따라 Git 추적에서 제외된다. 웹 지도 데이터는 이 수집 작업으로 변경하지 않는다.
